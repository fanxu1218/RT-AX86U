## 适配内容

| 文件 | 适配目的 |
|---|---|
| `install.sh` | 保留 UU 根目录安装包和原厂日志，移除全局 drop_caches，保留许可证/来源说明，使用原厂认证的 HTTP 管理路径 |
| `uninstall.sh` | 修正总为真的 jq 判断；保留其他插件仍需使用的共享 jq |
| `ss/ssconfig.sh` | 使用经原厂认证的 HTTP 查询，避免自动启动独立的 803 管理监听 |
| `webs/Module_shadowsocks.asp` | 使用上游已有的 HTTP 状态、配置和日志流程 |
| `scripts/ss_update.sh` | 将插件内更新引导至经过软件中心事务保护的兼容包 |

代理 ELF 文件保持上游原始字节。兼容包包含 GPL-3.0 许可证及来源/修改说明。WebSocket 专用的实时流功能不在本轮已验收范围内。

软件中心同时增加两条按完整 SHA256 限定的运行时适配：FRPC 已核对的安装脚本只清理自己的 `/tmp/frpc`；PushPlus 已核对的配置脚本通过原厂 HTTPS 回调返回请求 ID。生成结果再次核对哈希；临时文件冲突时保留原文件并拒绝安装。未知脚本不做自动改写。

软件中心在自定义卸载脚本成功后，统一清理该插件两个准确命名的卸载入口；自定义脚本失败时保留入口及登记。安装/更新检查点的保证不包含卸载脚本中途断电后的回滚。

## 本地验证

测试范围覆盖 Fancyss 3.5.28 → 3.5.29、FRPC 1.7 → 2.4（内核程序 0.65.0）、PushPlus 0.4 → 0.7，以及清空插件后的当前版新装、卸载、共享依赖和 UU 共存。FRPC/PushPlus 当前版本按固定上游源码和其 HND 打包配方生成，仅设置上游构建脚本声明的版本/平台并选择原始 ARM 二进制。软件中心的哈希限定适配在安装时执行。

本轮完整流程的 **26 项唯一检查通过**，源码/二进制绑定见 `fancyss_tests.json`；安装器另通过 **28 个归档案例和 19 项流程回归**。开发中的失败日志只用于定位问题，不能记为通过。Xray 检查验证 SOCKS → VLESS → 本地服务的真实转发，并验证默认私有地址保护和上游断开后的行为；测试仅在专用端口作精确放行，不修改生产默认策略。

安装入口已在 Chrome 桌面本地模拟页面检查布局和文字，模拟页未点击安装；实际安装请求由隔离 VM 通过原厂认证 API 和下载器验证。Fancyss 主界面的静态资源路径核对未发现缺失；主界面完整浏览器交互、移动布局及实机浏览器仍待验收。

隔离 VM 没有网卡或物理设备透传，主机工作区只读。共存测试使用 128 MiB RAM JFFS，并通过真实填充文件制造检查点空间不足；这不改变生产设备 JFFS 容量。原厂 HTTPS/登录、软件中心数据库/监督器和下载校验流程实际执行，UU 使用受控的本地 API 和自有心跳工作进程。

尚未验收：物理路由器启动与刷写、原厂 4.1.52 内核/iptables、真实代理节点/订阅与 WAN、透明代理的 DNS/IPv6/NAT、真实 UU 账号/游戏流量、真实 NAND 断电。软件包身份检查在 VM 中使用显式 uname 夹具，不把 Alpine 6.12 内核当作原厂内核。

## 官方底包升级时

GitHub 保存的是可复用的适配源码、固定输入和构建/回归脚本。更换官方底包需要重新检查原厂登录/TLS、rc 启动流程、共享库和防火墙等接口，再构建与回读新候选。直接刷官方固件会覆盖官改功能；跨底包的配置和插件兼容性需要重新验收。第二轮已加入 `base_migration.py` 底包差异/接口审计及独立 VM 回归入口，减少重复排查；不同底包仍须审查、重新构建和完整验收。
