# localmod2-r7 本地持续运行验证

本轮不连接或刷写路由器。测试对象为已发布的 r7 镜像，SHA256 为 `989ce7d6f5863ca450dea0857bd483cb40757f6089113c9fcbdb51891704e677`。本轮测试代码不进入固件。

## 时长与场景

入口：`python3 build/check_soak.py`；短周期预检入口：`python3 build/check_soak.py --smoke`。正式运行在同一台虚拟机中，从软件中心、真实 DDNS-Go 插件和自有 UU 工作进程启动并验收后，使用单调时钟计满 30 分钟；安装、证书生成和预检耗时不算入正式时长。

按约每秒一个请求交替查询 DDNS-Go 状态及版本；夹具关闭 HTTP keepalive，每次建立独立 HTTPS 连接。穿插以下事件：

- 客户端在后端正文仍待接收时发送 TCP RST。
- 客户端只发送一半 POST 请求体后断开。
- 后端 httpdb 处理查询时被强制终止，由原有监督进程重新启动。
- 用生产 bootstrap 重启软件中心，同时持续查询。
- 用一次原插件 RPC 重启 DDNS-Go，随后在重启窗口继续查询。
- 重新运行原厂 NTP→UU 下载/校验启动控制流程和自有工作进程，同时要求软件中心查询不中断。
- 重启原厂 HTTPS 服务，核对证书指纹、原后端及新登录会话。
- 在接收后端正文期间重复发送真实 SIGALRM。

所有请求使用新的 ID，不自动重发同一次 RPC。客户端主动丢弃的请求以及明确维护窗口中的暂时不可用单独记录，不混入正常运行成功率；每个事件完成后立即严格核对后续独立查询。UU 重启期间的查询必须成功，不能用维护窗口掩盖失败。认证拒绝不作为预期维护结果。

## 数据及资源观察

逐字节核对 DDNS-Go 配置、原厂证书存档、UU 合成持久化缓存/状态和临时下载文件；通过原生 dbus 核对插件记录。验证 UU 心跳及预期启动次数、DDNS-Go 本地页面和私有 API 源端口保护。记录各进程 PID、RSS 和文件描述符数量及正常查询延迟。

测试虚拟机无外部网卡，宿主工作区只读，根目录及 JFFS 均为可丢弃内存副本。真实第三方脚本只在 guest 中运行。最小 guest 的 PID 1 是 shell，测试专用 subreaper 只回收已经成为孤儿的退出进程，模拟正常 init 的回收职责；不终止正在运行的服务，也不回收仍有父进程的子进程。

30 分钟资源采样只说明这一段测试中观察到的范围，不能证明不存在缓慢泄漏。QEMU 进程 RSS 还包含仿真开销。原厂 4.1 内核、实机闪存、真实 UU monitor/账号/游戏加速、WAN DNS 服务及多天运行均不在本轮已验证范围。

## 结果

正式结果以 `soak-30m_tests.json` 和 `soak-30m.log` 为准，报告绑定上述固件 SHA256，并给出实际起止 UTC 时间、有效运行时长、查询数、各类事件、维护窗口和资源样本。`soak_preflight.log` 是进入正式计时前的短周期预检，不能代替正式运行结果。

### 本轮实测

- UTC：`2026-10-31T12:42:33Z` 至 `2026-10-31T13:12:37Z`；有效运行 `1803.532` 秒。
- 正常阶段 `1798` 次查询，无计划外失败；另记录维护窗口内查询及预期的 503/未运行状态，不把这些混为正常成功。
- 共 `19` 次事件：客户端 RST 3 次、半请求体断连 3 次、后端强制终止 3 次；软件中心、DDNS-Go、UU、HTTPS 服务各重启 2 次，重复 SIGALRM 2 组。
- 两次 UU 重启期间各有 9 次并行查询，均成功；UU 启动总数为 3，符合初始启动加两次计划重启。
- 插件配置及原生数据库记录、证书、UU 合成缓存和状态逐字节保持一致；私有 API 保护检查通过。
- 正常查询延迟中位数 `673.200` ms，P95 `785.603` ms，最大 `1549.604` ms。
- 样本中的文件描述符范围：HTTPd 5、httpdb 6、skipd 8、DDNS-Go 7、UU 工作进程 4–5。

DDNS-Go 单个进程生命周期样本内的 RSS 最大增长为 `7024` KiB，约 `6.86` MiB，呈阶梯变化。尚未区分运行时/缓存、QEMU 开销与潜在缓慢泄漏，不能宣称长期无泄漏。本轮没有据此修改固件的内存策略；这是报告中保留的待查资源趋势。

本轮未复现需要修改固件的功能故障，因此仅同步测试、夹具与报告，r7 固件 SHA256、发布标签及原有 24 个附件保持原样。
