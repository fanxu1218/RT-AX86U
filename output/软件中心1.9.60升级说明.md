# 软件中心 1.9.60 升级说明

当前工作分支：localmod2-r9-r1。此文件随本轮候选固件更新；最终是否完成构建，以同版本 `verification.json` 和 `release_gates.json` 为准。候选已完成构建及 19 项镜像回读校验，软件中心与 Fancyss 共存的 35 项检查已通过；完整本地发布门禁已通过，实际设备仍未验收。

来源为 KoolCenter HND 发布包 1.9.60，对应 koolshare/rogsoft 提交 `55b5e9827d6e32a1036a02de3fa725a4d80099a0`。包 SHA256 为 `ae0df46dba72ad497be40234610f705e948d7629dd7674f3069fea01544b623a`；长度、发布 MD5、平台标记、归档路径和版本均经过校验。

新版界面和资产直接来自发布包。修正了包中两处符号链接的权限元数据：按 Linux 链接语义统一为 0777，内容和目标不变；避免镜像回读出现包记录 0755、实际 inode 0777 的差异。调试入口改为已经过原厂登录保护的版本说明页。数据服务继续绑定回环地址，通过原厂 HTTPS 会话访问；固件维护的引导、安装事务、检查点保护和 UU 兼容策略继续生效。

普通 HND 插件仍使用软件中心安装、升级和卸载。新版前端的升级请求不重复提交软件源地址，安装器应复用原安装记录中的来源。实际发布 JavaScript 生成的请求会进入本地原厂 HTTPS 和真实安装器验证，避免只验证手写请求。

Fancyss 仍使用本项目校验过的兼容包。已适配的 3.5.28 和 3.5.29 会保留 UU 路径，并进入受控安装和恢复流程。上游原包会删除 UU 文件，因此直接使用原包、绕过检查点或直接覆盖软件中心核心的操作继续受到限制。新版本 Fancyss 需要先完成相同的适配与验证；本轮不包含任意版本免验证升级通道。

升级模型使用原 r9 镜像中真实的 1.9.50 核心和合成 JFFS，在保留真实 Fancyss 配置结构、测试节点及 UU 测试数据的情况下，由新引导升级到 1.9.60。浏览器模拟界面验证、前端函数验证和原厂服务验证分别记录，不能相互替代。

同镜像软件中心专项为 `softcenter_upgrade_tests.json` 九项，发布前端函数为 `softcenter_frontend_tests.json` 七项，完整 Fancyss/FRPC/PushPlus 与核心迁移组合为 `fancyss_tests.json` 35 项。`softcenter_ui_mock_tests.json` 另为浏览器模拟服务验证，不能代替原厂 HTTPS 运行检查。新版更新请求没有重复提交软件源字段，真实安装器成功复用既有来源并保留配置；同版本跳过也已验证。这些本地测试均不代表真实 UU 账号、实际加速、外网节点或物理路由器已经验收。

现有 r9 镜像和本地交付包予以保留。回退刷机及跨版本配置恢复仍按《Alpha3升级localmod2与实机验收》执行；本轮没有访问或刷写实际路由器，也没有推送 GitHub。
