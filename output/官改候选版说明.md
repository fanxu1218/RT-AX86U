# RT-AX86U 官改实验候选版 localmod2-r6

修订日期：2026-10-31。基于 ASUS 3.0.0.4.388_24437，集成软件中心 1.9.50，保留官方网易 UU 实现。**当前仍为未实机验收的开发候选版，暂不建议直接刷入日常主路由。此次没有连接或刷写路由器。**

## r6 损坏检查点与恢复空间不足

r5 的五项隔离对照复现了：损坏配置被接受并启动中心，缺失 `ready` 或错误 `committed` 导致检查点被清理，数据库截断和重放时真实写满虚拟 JFFS 后遗留 skipd。对照镜像 SHA256 为 `e55a5178bc4d11a9bc90772362753ee9cc73d644d870a8c572ab5b9376768841`，记录见 `recovery_r5_baseline.json` 和五份 `recovery_r5_baseline_*.log`。

r6 的新格式检查点使用 SHA256 封存清单和提交凭据，先完整核对数据、元信息、键值结构及剩余空间，再移动任何恢复目标。丢失或损坏的标记、清单、文件、元信息，以及无效目录/链接都会保留可用副本并停止启动中心，不把不明状态当成未开始的准备过程。

重放前保守预留 `2 MiB + 3 × 逻辑记录字节数`，运行时仍处理提交和写入失败；不会删除 UU 缓存或历史记录来腾空间。失败时结束本次新建的重放数据库，原始数据库和检查点保留。重放成功后关闭并重开原厂 skipd，核对完整键值集合，避免只读取到未落盘的内存值就宣布恢复完成。

新格式为版本 2。r5 版本 1 没有可信封存清单，r6 不为已有未知字节补算校验后自动采用；遇到活动的旧记录会保留现场、暂停软件中心，要求人工核查。正常完成安装、没有活动旧记录的 r5 升级不受此限制。损坏字节无法从哈希重建，仍需要原始可信备份。

最终 r6 镜像新增 11 类损坏/空间场景、94 项检查通过，共 23 次独立虚拟机启动；原有中断回归 69 项、真实插件 32 项、在线管理 28 项及证书/共存 17 项也通过。

验证入口为 `python3 build/check_recovery_safety.py`。其故障只作用于自有 96 MiB 虚拟磁盘，JFFS 空间用 guest 内的真实块分配耗尽；日志、目录及逻辑记录保留后检查原厂登录/TLS、UU 控制流程和合成数据，修复夹具或释放空间后以新虚拟机恢复并重试。旧格式由固定 r5 提交重编译的辅助程序生成，二进制 SHA256 与已发布 r5 报告一致。它只进入测试 guest，不进入固件。

本轮仍未操作路由器，也不代表真实 NAND/UBIFS、原厂内核故障或 UU 账号/加速已验收。具体结果绑定最终镜像，见 `recovery_safety_tests.json`。

测试夹具另修正了就绪标记与 `pause()` 之间的信号竞态：发布就绪时先屏蔽信号，用 `sigsuspend()` 原子恢复原信号掩码并等待。仍由原厂处理函数接收一次真实信号，保留有界等待和超时现场日志；该调整不进入固件。

测试基础设施另出现过 Alpine 6.12.114 在格式化或挂载自有虚拟磁盘时的内核异常，尚未进入插件恢复；已保留本地诊断，核对内核/相关模块与固定安装包一致，重建 initramfs 字节未变。后续使用单 vCPU 的磁盘测试虚拟机完成续跑。原因未确认，不把更改 vCPU 数记作修复；报告保留分段验收及已完成日志哈希。

本轮首次真实插件回归曾在 DDNS-Go 只读状态查询收到 HTTP 200 后连接提前关闭；增加原厂 HTTPd 日志诊断后，新虚拟机完整重跑的 32 项检查通过，包含四次独立状态查询，没有在原请求上重试。该偶发问题的原因仍未确认，不记作已修复固件缺陷。

## r5 安装中断恢复

r4 的受控中断复现发现：安装脚本迁移了一半配置后被杀，会留下不完整的活动配置；临时操作锁阻止重试，而 `/tmp` 中的卸载器副本不能跨重启恢复。静态检查还发现离线脚本仍会全局清理 `/tmp/*.tar.gz*`，可能删除 UU 的临时下载。

r5 在执行安装脚本前保存持久化文件/数据库检查点，已进入脚本但未提交的更新在下一次启动回退；未落盘的新内容不能保证保存，存储中仍可读取的中断现场单独保留。新事务不在同一次启动中覆盖旧检查点，避免遗留子进程继续写入。已封存提交的更新保留新版，垃圾清理再次中断不触发误回退。

在线与离线安装共用锁及检查点，软件中心 POST 在事务期间返回 423；原厂登录/TLS、日志和 UU 页面不受此写入门禁影响。离线安装使用私有下载/解压范围，不批量清除 UU 或其他上传包。准备失败、检查点复制失败或空间不足时不执行安装脚本。

`plugin_txn.c` 使用原 skipd 帧协议保存、重放长度记录，避免多行、引号和美元符号被解释为脚本；不复制正在使用的原始数据库作为回滚来源。恢复前隔离中断的文件树和原始数据库，重放再中断也保留副本。历史不自动删除且可能含用户凭据，应私下备份，禁止上传公开仓库。

11 类场景、69 项检查通过，共启动 24 次独立虚拟机。覆盖下载/检查点准备、杀安装父进程/进程树、离线/新装/真实 DDNS-Go 更新、提交前后和清理中断、写入 ENOSPC、文件恢复和数据库重放再次中断，以及同一启动重复恢复拒绝。恢复后的在线、离线、新插件及真实插件重试均通过。

完整规则、恢复步骤及测试边界见 [插件安装中断恢复说明](插件安装中断恢复说明.md)，结果见 `interruption_tests.json` 与 `interrupt_*_*.log`；公开发布不包含虚拟磁盘、私钥或用户数据。修复独立发布为 `localmod2-r5-experimental`，r4 及更早附件保留。

本轮在完整原厂根目录中执行真实插件，复现了此前 Alpine 工具环境掩盖的问题。修复使用独立的 `localmod2-r4-experimental` 镜像和标签，r3 及更早的固件附件保留。没有连接、备份或刷写任何路由器。

|---|---|---|---|
| 阿里 DDNS | 2.1 → 软件中心目录 2.4 | 2.2 | [Koolshare 历史原包](https://github.com/koolshare/rogsoft/tree/4100df46ea63c0c59568636c0ff9af6391592e59/aliddns)、当前 rogsoft CDN |
| DDNSTO | 3.0.3 → 软件中心目录 4.2.2 | 4.2.0 | [Koolshare 历史原包](https://github.com/koolshare/rogsoft/tree/96cefeb5489beaede5a3421ba02746b56d396973/ddnsto)、当前 rogsoft CDN；[上游项目](https://github.com/linkease/merlin_ddnsto) |
| DDNS-Go | 1.28.0 → 1.29.0 | 1.29.0 | [上游历史提交](https://github.com/2TimesMeta/koolcenter_ddnsgo/tree/ea34fb143772d44b064bf5592035419d5dede3dd)、当前 rogsoft CDN |

阿里 DDNS、DDNSTO 的目录版本与包内 `version` 不一致，报告分别保留两者。DDNS-Go 1.28.0 使用固定提交中的原始 `ddnsgo/` 文件重新打包，没有改脚本、程序或版本号；其余五个包直接使用原发布字节。六组包、源归档及逐文件 SHA256 均固定在 `build/real_plugin_sources.json` 和最终报告中，不通过伪造版本号模拟升级。公开仓库不收录这些第三方安装包。

修复四类问题：

1. 原厂 `/usr/sbin/sh` 是 `/bin/memaccess` 的半字写入别名。此前 bootstrap/dispatch 的 PATH 把它排在 `/bin/sh` 前，软件中心启动错误调用内存工具，未启动后台却返回成功。现在沿用原厂 `/rom/etc/profile` 的工具顺序，保留原别名。
2. 原厂 curl 拒绝数字 IP URL，并可能返回 0 却不发请求。原回调 `http://127.0.0.1:3032` 因此失效；现使用 `localhost`，通过 `--resolve localhost:3032:127.0.0.1` 强制连接回环，仍禁止代理并使用 600–1023 源端口。原厂 curl、URL/调用方保护及私有 API 防火墙不变。
3. 原厂 BusyBox 未编入 `tee`、`xargs`，而中心/真实插件依赖它们记录结果和清理文件。现在将固定 donor 的 BusyBox 放在私有 `/usr/libexec/localmod/busybox`，只新增这两个命令链接；原厂 `/bin/busybox` 字节保留。
4. 已启用的 DDNS-Go 会创建空 `/tmp/ddnsgo`，r3 将其误判为其他任务，拒绝更新。现在仅对已登记插件使用 `rmdir` 复用空的真实目录；非空目录、符号链接、未登记插件的同名目录或竞争失败仍拒绝，保留数据。

32 项真实插件检查全部通过：升级虚拟机 22 项、当前版全新安装虚拟机 10 项。覆盖三款插件的原文件安装、真实旧版升级、配置保留、认证模块页面、自带卸载与登记/脚本/图标/启动链接清理；DDNS-Go 额外运行真实本地网页、状态/版本回调、perp 监督、WAN/NAT 事件和软件中心重启恢复。每次保留其他插件、UU 进程/缓存与证书。另回归 28 项受控在线管理检查（新增未登记空目录与已登记符号链接拒绝）、17 项证书/共存及原有事件/原程序检查。

实际执行的 DDNSTO 二进制报告 `4.2.2`，DDNS-Go 二进制报告 `v6.17.7`，与插件包版本分别记录。插件网页的只读 RPC 使用 `fields: ""`，返回状态/版本文字；测试按该真实协议检查，不把它误当作返回请求 ID 的保存回调。

验证入口为 `python3 build/check_real_plugins.py`，完整构建也会运行。实际调用原厂 HTTPS 登录、认证 API、curl/wget 和打包的 `start-stop-daemon`、httpdb/perp/skipd/dbus；真实插件的安装、配置、卸载脚本和程序不替换为测试实现。DDNS-Go 的 ARM 程序及本地网页实际运行；阿里 DDNS、DDNSTO 验证配置保留、关闭状态回调和安装/卸载，DDNSTO 另外执行原二进制版本查询，不声称云服务可用。

宿主工作区只读导出，虚拟机无外网网卡或物理磁盘，完整候选根目录复制到内存，JFFS 为 64 MiB tmpfs。ARM `binfmt_misc` 的 F 标志允许在 chroot 中执行原程序；进程读取真实 guest proc，不再用 Alpine 启动工具替代插件的安装/卸载执行器。结果通过有大小和时间上限的串口返回，插件没有可写宿主目录。原理见 [Linux binfmt_misc 文档](https://www.kernel.org/doc/html/latest/admin-guide/binfmt-misc.html)。

UU 仍由原厂 rc 的 NTP→下载→校验流程启动自有 monitor/心跳进程。每次插件检查核对其 PID/心跳与单次启动、缓存、证书存档、无关文件、原厂 UU 页面、其他插件及私有 API 隔离。**未运行真实 UU monitor，未测试 UU 账号、游戏流量加速、阿里云 API、DDNSTO 云隧道或 DDNS-Go 服务商认证。** Alpine 6.12 内核与原厂 4.1/iptables 的 ABI 差异使用 guest 原生 legacy xtables 边界处理，不能替代目标设备的规则验证。

证据见 `real_plugins_r3_reproductions.log`、`real_plugin_tests.json` 和两份 `real_plugins_*_tests_run.log`。安装器拒绝非空运行目录是保留数据的设计限制。上述 r4 测试组本身不覆盖中断；r5 的定义范围恢复由独立报告验证，任意外部改动及实机断电仍未验证。

## r3 在线插件管理与 UU 共存修复

2026-10-31 从 r2 的在线脚本复现并修复以下问题，使用独立的 `localmod2-r3-experimental` 标签和文件，r2 及更早附件保留：

- 安装普通插件时，脚本会删除 `/jffs` 下的 `uu.tar.gz*`、`/tmp/*.tar.gz*` 和其他 `install.sh` 所在目录。现在下载保存在私有操作目录，只清理本次新建的 `/tmp/插件名`；已存在目录会保留并拒绝覆盖，UU 缓存和无关任务不受平台清理影响。
- 更新包先覆盖卸载器，安装失败又删除它，导致仍在运行的旧版本丢失卸载入口。现在先备份，失败时恢复原文件，平台不推进版本登记。
- 两种自定义卸载入口未完整检查退出码，失败仍删登记并显示成功；默认卸载按前缀删除，误删相似名称插件。现在失败时平台停止后续删除登记/配置，默认清理使用模块名称边界。
- 原进程检查引用错误变量，不能阻止重叠在线操作。现在进入在线脚本时先取得互斥锁，再快照请求字段；拒绝重叠请求并保留活动操作。结束时传递真实结果，修复低空间分支调用不存在函数及管道吞掉退出状态的问题。
- 共存回归两次观察到停用后监督进程及 httpdb 残留。原停止脚本只发送信号且不等待；现在确认监督进程退出后再停止后台，采用有界等待和必要的无状态进程强制退出。skipd 仍通过原提交屏障关闭，不强杀数据库。

新增 26 次流程检查分三台全新虚拟机运行：安装/升级/断流重试/同版或降级跳过/卸载；404、MD5 错误、坏包、目录不匹配、缺少 install.sh、不受信 CA、主机名错误、更新脚本失败、预存目录、低 JFFS 空间；并发 RPC、两种卸载失败、默认卸载边界及核心/无效标识拒绝。每次检查均核对自有 UU 进程心跳/单实例、UU 缓存、无关临时文件、证书存档、原厂 UU 页面和私有 API 隔离。自有插件实际运行工作进程和安装后的 RPC 回调，更新保留用户配置。

下载使用**字节保留的原厂 wget 1.20.1**。测试仓库使用专用域名解析到虚拟机回环地址，显式信任自有 CA；不受信 CA 和错误主机名被原厂 wget 拒绝。没有修改原厂下载地址/调用者保护，也没有为插件下载关闭证书校验。公网目录只读核对了 JSON/字段协议，没有执行真实第三方插件。UU 下载仍为本地受控响应和自有 monitor/工作进程。

复现记录见 `online_r2_reproductions.log`，当前镜像结果见 `online_plugin_tests.json` 及三份 `online_*_tests_run.log`。入口为 `python3 build/check_online.py`。测试使用合成 NVRAM/账号、Alpine 内核/部分工具及 CPU/proc 包装，**不能替代实机、真实公网下载、真实第三方插件和 UU 流量验证**。该 r3 测试组只检查平台管理的卸载器/登记，不覆盖中断。r5 新增的软件中心文件/skipd 检查点由独立报告验证；任意外部改动与实机断电仍不在已验证范围。

## r2 原厂登录/TLS 与 UU 本地运行

本轮使用字节保留的原厂 HTTPd、libpasswd、mssl/OpenSSL 和 rc，在无外网网卡的 Linux 虚拟机内运行。仅提供合成的 NVRAM、shadow 账号、临时证书和私有 LAN 地址；不替换原厂密码、会话校验或 TLS 函数。UU 的 DNS/服务通知边界受控，下载由仅允许本地地址的 wget 测试入口交给 Alpine curl；原厂校验与启动分支仍实际执行。

复现并修复四个 r1 模型未覆盖的问题：

- 其他库的构造函数先调用 stdio 时，适配库的原函数指针尚未初始化。现在在首次拦截调用时也解析原函数，避免初始化顺序导致的崩溃。
- 原厂 `invalid_program_check` 拒绝 `/tmp/.localmod/httpd` 执行路径。现在直接运行只读 `/usr/libexec/localmod/httpd`，保留原文件、basename 和路径检查，不再复制到 `/tmp`。
- 原厂 HTTPS 登录颁发 `asus_s_token`，而旧适配只识别 `asus_token`。现在精确识别两种 Cookie 名称，仍由原厂验证其有效性和传输上下文。
- 原厂认证页面输入处理会预读字节，导致随后转发的 POST 请求体丢失并超时。现在包装请求的预读返回 EOF，原请求体由认证后的代理转发流程消费。

新增 24 项运行与配套检查：HTTP 与 HTTPS 各 8 项，覆盖登录页、错误密码、真实 Cookie 签发、受保护页面、软件中心读取、POST 字段及回调、缺失/错误会话和退出失效；原厂 rc 的 NTP SIGTSTP→UU 覆盖 6 个场景，包括正确下载/校验/自有脚本启动、重复同步不重启、错误校验、下载失败、异常响应、地区及模式限制；另检查早期 stdio 与只读执行路径。TLS 客户端显式信任临时测试 CA 并验证链和主机名，没有关闭验证。

这些结果证明原厂代码在所述合成环境中的行为；**未登录真实 UU、未运行下载的真实 UU monitor、未校验游戏流量或实机启动。** 详见 `native_runtime_tests.json` 及两份 native 运行日志。

## r2 后续证书生命周期与共存复核

2026-10-31 追加 17 项检查，并复跑上述 24 项原程序运行及配套检查。**本轮没有复现需要修改生产适配或原厂程序的缺陷，已发布的 r2 镜像及 SHA256 保持原样。** 更新内容是测试夹具、复跑入口及验证记录。

8 项证书检查实际执行原厂 HTTPd、libshared 的 `save_cert`/`restore_cert`、原文件 `gencert.sh` 和 OpenSSL：

- 从空证书目录自动生成 CA/服务器证书；校验私钥配对、CA 链、LAN IP SAN、私钥权限和真实 TLS 握手，没有关闭客户端验证。
- `/jffs/cert.tgz` 包含 8 个证书/密钥文件，逐一与原文件比对；HTTPS 进程重启复用原证书。
- 故意换成不匹配的服务器私钥后，原厂恢复有效存档中的正确配对。
- 在**另一台全新 Linux 虚拟机**中只放回上一台的自有存档，原厂恢复全部 8 个文件、原指纹、CA 导出链接及 `server.pem`，没有重新生成密钥。
- 损坏存档且清除易失证书后，原厂重新生成并保存有效证书；关闭保存时可生成 TLS 证书，但不创建持久存档。

9 项共存检查在同一虚拟机内运行实际打包的 perpboot/perpd/httpdb/skipd/dbus、生产 `bootstrap.sh`、原厂 HTTPS 和 rc：

- 原厂 TLS 登录后完成软件中心写入、字段读取和 curl 回调，原厂 UU 页面仍走独立路径。
- 中心已运行时，经原厂 NTP→UU 下载/校验/启动自有 monitor 和持续工作的自有测试进程；8 次并发中心/UU 页面请求通过。
- 3 次 filter 重载后，普通源端口不能访问私有 API；认证回调及测试进程保持正常。
- 中心重启保留数据库值和证书存档，HTTPS 重启保留证书、中心实例和测试进程；重复 NTP 通知没有再次下载或启动。
- 停用中心后，其后台和 API 停止，原厂 HTTPS/UU 页面及自有测试进程仍工作。

已更正测试环境中的提前判断监听端口、原程序执行路径和固定探测端口复用问题；未将它们记作固件缺陷。原厂密码、证书生成/保存/恢复和 TLS 函数均未替换，临时观测库不参与正式验证。合成账号和硬件模拟库未进入固件；测试私钥和证书存档不在公开附件中，跨虚拟机传递的自有存档在检查结束后删除。

报告为 `lifecycle_tests.json`，对应 `cert_generate_tests_run.log`、`cert_restore_tests_run.log` 和 `coexist_tests_run.log`。复跑入口为 `python3 build/check_lifecycle.py`。这些是无外网网卡环境中的进程/文件恢复和受控共存结果，**不代表真实闪存/NVRAM、断电耐久性、物理路由器重启、任意第三方插件或真实 UU 服务已通过。**

## 已有适配范围

| 事件或接口 | localmod2 行为 |
|---|---|
| `init-start` | JFFS 挂载成功、受管理核心准备完成后调用 |
| `services-start` | 官方 init 完成启动、进入等待前，以及系统重启流程完成后调用 |
| `services-stop` | 重启、停止、关机/HALT 前调用，并先完成排队中的事件 |
| `service-event` / `service-event-end` | 逐条处理分号分隔的 start/stop/restart 命令，传入动作与服务名 |
| `wan-event` / `wan-start` | 传入 WAN 单元及七种状态；connected 时兼容旧 wan-start，并防止 fork 重放父进程事件 |
| `firewall-start` / `nat-start` | 规则成功应用后调用；测试模式和失败不发事件 |
| `pre-mount` / `post-mount` / `unmount` | 保留设备、文件系统和挂载点参数；挂载事件完成后才卸载；卸载重试不重复执行插件 |
| DNS 配置 | 支持 dnsmasq.conf、.add、dnsmasq.d、dnsmasq.postconf 和常用 helper.sh 函数，先改配置再启动服务 |
| 核心兼容入口 | jffsinit.sh、kscore.sh、service start/stop/restart_skipd 与 softcenter 服务入口 |

事件队列保存在 `/tmp/.localmod`，限制为 root 访问。异步事件按队列顺序运行；阻塞钩子设有 120 秒脚本限时，超时清理子进程组。原有 `/jffs/scripts` 文件保持原样；即使旧用户钩子已调用软件中心 helper，同一事件也只运行一次对应 helper。带空格的挂载路径保持为一个参数。

NVRAM 适配不会为普通读取/写入插入额外 getter。脚本开关由独立 `/bin/nvram` 进程读取，避免覆盖厂商 getter 的共享缓冲区或借用参数。关闭 `jffs2_scripts` 会抑制用户钩子。

## 软件中心安装与迁移

- 首次从旧 Alpha 3 迁移时，旧 `.koolshare` 保存在 `.koolshare.pre-localmod`，原数据库仍保留，不自动激活旧插件。
- 已有 localmod 安装升级时，仅更新受管理核心，保留当前插件、数据库和用户钩子；不保留用户对核心文件本身的覆盖修改。
- 在线及离线覆盖软件中心核心均被拦截；普通插件仍可安装。
- skipd 停止前先通过有时限的读取屏障提交待写数据，再等待旧进程退出；修复立即写入后快速重启时丢失配置的问题。
- 修复离线安装脚本退出码及管道状态丢失，错误平台包和核心覆盖包明确返回失败。
- 运行目录改为隐藏的独立目录，避免插件安装清理普通 `/tmp/localmod*` 目录时碰到官改进程状态。
- HTTPd API 兼容编码查询参数和上传查询参数，继续拒绝编码路径穿越；登录认证仍交给官方服务。
- 停用标记会关闭私有 API 后台；HTTPd/rc 启动器会在停用状态直接运行保留的官方程序。

## 防火墙兼容

标准 `iptables-restore` 入口保留原厂 xtables 程序和退出状态，将 API 隔离规则与 filter 表放在同一个 COMMIT 中应用。支持 stdin、文件输入、noflush、测试模式及错误退出。

另适配了 HND 非路由模式下原厂 `iptables -t filter -F` 调用：保留链定义和策略，清空原规则时同时保留 API 隔离，不提前伪造 firewall-start。通过其他 iptables 入口显式删除保留规则、任意第三方防火墙工具及原厂目标内核上的完整行为，仍需进一步验证。

## 验证结果

- 回读 3,597 个路径，内容、链接、权限、UID/GID 均匹配；未带入 macOS 扩展属性。

- 实时 netfilter 测试完成 24 次完整表重载和 5 次非路由清空，60,560 次普通源端口连接探测全部被拒绝，特权源端口可连接。
- 使用实际打包的 httpdb、skipd/dbus 经认证适配层完成受控测试插件的 multipart 上传、离线安装、字段读取、脚本回调及自定义卸载；错误平台、核心覆盖和停用标记关闭后台均通过。

测试边界：早期事件及兼容测试的官方 rc 硬件动作和登录认证使用模型；新增 native 测试实际运行原厂登录、会话、TLS 与 NTP/UU 控制流，使用合成 NVRAM/账号/证书和受控传输。实时网络测试使用 ARM64 Linux 6.12 与 Alpine xtables 1.8.11。受控安装使用 Alpine curl 和进程启动 helper，QEMU 进程使用目标名称以便验证 pidof/killall 生命周期。**这些结果不代表真实原厂 rc、HTTPd TLS、内核 4.1 或 xtables 1.4.12.2 已在路由器上通过。没有联网安装任何第三方插件。**
