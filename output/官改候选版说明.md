# RT-AX86U 官改实验候选版 localmod2-r2

修订日期：2026-10-31。基于 ASUS 3.0.0.4.388_24437，集成软件中心 1.9.50，保留官方网易 UU 实现。**当前仍为未实机验收的开发候选版，暂不建议直接刷入日常主路由。此次没有连接或刷写路由器。**

## r2 原厂登录/TLS 与 UU 本地运行

本轮使用字节保留的原厂 HTTPd、libpasswd、mssl/OpenSSL 和 rc，在无外网网卡的 Linux 虚拟机内运行。仅提供合成的 NVRAM、shadow 账号、临时证书和私有 LAN 地址；不替换原厂密码、会话校验或 TLS 函数。UU 的 DNS/服务通知边界受控，下载由仅允许本地地址的 wget 测试入口交给 Alpine curl；原厂校验与启动分支仍实际执行。

复现并修复四个 r1 模型未覆盖的问题：

- 其他库的构造函数先调用 stdio 时，适配库的原函数指针尚未初始化。现在在首次拦截调用时也解析原函数，避免初始化顺序导致的崩溃。
- 原厂 `invalid_program_check` 拒绝 `/tmp/.localmod/httpd` 执行路径。现在直接运行只读 `/usr/libexec/localmod/httpd`，保留原文件、basename 和路径检查，不再复制到 `/tmp`。
- 原厂 HTTPS 登录颁发 `asus_s_token`，而旧适配只识别 `asus_token`。现在精确识别两种 Cookie 名称，仍由原厂验证其有效性和传输上下文。
- 原厂认证页面输入处理会预读字节，导致随后转发的 POST 请求体丢失并超时。现在包装请求的预读返回 EOF，原请求体由认证后的代理转发流程消费。

新增 24 项运行与配套检查：HTTP 与 HTTPS 各 8 项，覆盖登录页、错误密码、真实 Cookie 签发、受保护页面、软件中心读取、POST 字段及回调、缺失/错误会话和退出失效；原厂 rc 的 NTP SIGTSTP→UU 覆盖 6 个场景，包括正确下载/校验/自有脚本启动、重复同步不重启、错误校验、下载失败、异常响应、地区及模式限制；另检查早期 stdio 与只读执行路径。TLS 客户端显式信任临时测试 CA 并验证链和主机名，没有关闭验证。

这些结果证明原厂代码在所述合成环境中的行为；**未登录真实 UU、未运行下载的真实 UU monitor、未校验游戏流量或实机启动。** 详见 `native_runtime_tests.json` 及两份 native 运行日志。

## r1 此前的本地复核与修复

- 复现并修复 Alpha 3 的 `.asusrouter` 在核心目录改名后变成悬空链接、未被归档的问题；对备份链接的冲突检查在移动旧核心前完成，失败时保留活动旧核心。
- 复现并修复上游 `插件名_uninstall.sh` 文件判断缺少空格的问题；实际安装的受控插件自带卸载脚本现在经 RPC 执行，注册项和模块页面均清除。
- 将真实 multipart 上传、安装 RPC、字段读取、curl 回调和卸载串接到 ARM32 认证适配层，后端使用打包的 httpdb/skipd/dbus；上传采用界面原有的“文件名作为表单字段名”约定。
- 新增 UU 官方 rc/页面/图标、官方入口与设备标签 MAC 生成逻辑的原样保留检查；模型验证 UU 风格命令的参数、环境、超时、PID 输出和返回值不被适配器改写，UU 页面及带查询请求不会被代理到软件中心。
- UU 风格命令由 mock vendor `_eval` 核对，**没有运行下载的 UU monitor、登录账号或验证加速**。`uu_compatibility_tests.json` 明确列出这一边界。
- r1 及原 localmod2 预发布保留；本轮使用独立的 `localmod2-r2-experimental` 标签。

## 已有适配范围

| 事件或接口 | localmod2 行为 |
|---|---|
| `init-start` | JFFS 挂载成功、受管理核心准备完成后调用 |
| `services-start` | 官方 init 完成启动、进入等待前，以及系统重启流程完成后调用 |
| `services-stop` | 重启、停止、关机/HALT 前调用，并先完成排队中的事件 |
| `service-event` / `service-event-end` | 逐条处理分号分隔的 start/stop/restart 命令，传入动作与服务名 |
| `wan-event` / `wan-start` | 传入 WAN 单元及七种状态；connected 时兼容旧 wan-start，并防止 fork 重放父进程事件 |
| `firewall-start` / `nat-start` | 规则成功应用后调用；测试模式和失败不发事件 |
| `pre-mount` / `post-mount` / `unmount` | 保留设备、文件系统和挂载点参数；挂载事件完成后才卸载；卸载重试不重复执行插件 |
| DNS 配置 | 支持 dnsmasq.conf、.add、dnsmasq.d、dnsmasq.postconf 和常用 helper.sh 函数，先改配置再启动服务 |
| 核心兼容入口 | jffsinit.sh、kscore.sh、service start/stop/restart_skipd 与 softcenter 服务入口 |

事件队列保存在 `/tmp/.localmod`，限制为 root 访问。异步事件按队列顺序运行；阻塞钩子设有 120 秒脚本限时，超时清理子进程组。原有 `/jffs/scripts` 文件保持原样；即使旧用户钩子已调用软件中心 helper，同一事件也只运行一次对应 helper。带空格的挂载路径保持为一个参数。

NVRAM 适配不会为普通读取/写入插入额外 getter。脚本开关由独立 `/bin/nvram` 进程读取，避免覆盖厂商 getter 的共享缓冲区或借用参数。关闭 `jffs2_scripts` 会抑制用户钩子。

## 软件中心安装与迁移

- 首次从旧 Alpha 3 迁移时，旧 `.koolshare` 保存在 `.koolshare.pre-localmod`，原数据库仍保留，不自动激活旧插件。
- 已有 localmod 安装升级时，仅更新受管理核心，保留当前插件、数据库和用户钩子；不保留用户对核心文件本身的覆盖修改。
- 在线及离线覆盖软件中心核心均被拦截；普通插件仍可安装。
- skipd 停止前先通过有时限的读取屏障提交待写数据，再等待旧进程退出；修复立即写入后快速重启时丢失配置的问题。
- 修复离线安装脚本退出码及管道状态丢失，错误平台包和核心覆盖包明确返回失败。
- 运行目录改为隐藏的独立目录，避免插件安装清理普通 `/tmp/localmod*` 目录时碰到官改进程状态。
- HTTPd API 兼容编码查询参数和上传查询参数，继续拒绝编码路径穿越；登录认证仍交给官方服务。
- 停用标记会关闭私有 API 后台；HTTPd/rc 启动器会在停用状态直接运行保留的官方程序。

## 防火墙兼容

标准 `iptables-restore` 入口保留原厂 xtables 程序和退出状态，将 API 隔离规则与 filter 表放在同一个 COMMIT 中应用。支持 stdin、文件输入、noflush、测试模式及错误退出。

另适配了 HND 非路由模式下原厂 `iptables -t filter -F` 调用：保留链定义和策略，清空原规则时同时保留 API 隔离，不提前伪造 firewall-start。通过其他 iptables 入口显式删除保留规则、任意第三方防火墙工具及原厂目标内核上的完整行为，仍需进一步验证。

## 验证结果

- 回读 3,596 个路径，内容、链接、权限、UID/GID 均匹配；未带入 macOS 扩展属性。
- UBI EC/VID 头、静态卷、256 个卷表记录、52,285 个 UBIFS 节点及整包 WFI CRC 通过，UBIFS 格式为 4。
- 原厂启动区域、rc、HTTPd、xtables-multi、UU 页面及全部内核模块通过字节比对。rc 和 HTTPd 原文件保留在独立路径，由新增启动器加载适配库。
- 21 项 ARM 事件模型检查、19 项兼容检查、7 项 UU 静态/模型检查及 24 项原程序运行与配套检查通过；事件模型覆盖启动器参数/退出码、多服务命令、所有 WAN 状态、fork 隔离、挂载/卸载、参数边界、重复执行、重启/HALT、NVRAM 共享缓冲区及超时。
- 实时 netfilter 测试完成 24 次完整表重载和 5 次非路由清空，64,829 次普通源端口连接探测全部被拒绝，特权源端口可连接。
- 使用实际打包的 httpdb、skipd/dbus 经认证适配层完成受控测试插件的 multipart 上传、离线安装、字段读取、脚本回调及自定义卸载；错误平台、核心覆盖和停用标记关闭后台均通过。

测试边界：早期事件及兼容测试的官方 rc 硬件动作和登录认证使用模型；新增 native 测试实际运行原厂登录、会话、TLS 与 NTP/UU 控制流，使用合成 NVRAM/账号/证书和受控传输。实时网络测试使用 ARM64 Linux 6.12 与 Alpine xtables 1.8.11。受控安装使用 Alpine curl 和进程启动 helper，QEMU 进程使用目标名称以便验证 pidof/killall 生命周期。**这些结果不代表真实原厂 rc、HTTPd TLS、内核 4.1 或 xtables 1.4.12.2 已在路由器上通过。没有联网安装任何第三方插件。**

## 停用适配

仅在此候选固件已启动且 SSH 可用时：

```sh
touch /jffs/localmod-disabled
service restart_httpd
```

后台会停止，重启的管理服务不再加载适配库。这不是无法启动或无法 SSH 时的恢复保证；CRC 通过也不代表设备会接受该镜像。
