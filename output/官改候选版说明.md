## 实际修改

- 将官方 HTTPd 原文件保留到 `/usr/libexec/localmod/httpd.vendor`，增加启动器和小型动态适配库，设计上继续由官方服务处理 HTTPS 和登录会话。软件中心 API 在通过官方认证后转到回环地址上的 httpdb。
- 将软件中心核心、skipd/dbus 和页面资源加入根文件系统，并适配 `/Module_*.asp` 和 `/res/` 的读取位置。原文件存在时优先使用原文件。
- 从 init 启动器派生初始化脚本，再执行未修改的官方 `rc`。新软件中心数据库使用独立目录。
- 首次启动逻辑会把旧 `/jffs/.koolshare` 备份为 `/jffs/.koolshare.pre-localmod`，保留原数据库，不自动导入旧插件。如果备份目录冲突、空间不足或已有中心进程运行，会停止新中心初始化，而不是覆盖旧数据。这些迁移行为尚未在路由器上验证。
- 移除捐赠固件的独立 LAN 调试/重置入口和梅林专用 bootstrap。软件中心的调试链接改为本地版本说明页。
- 拦截软件中心核心的在线升级，防止覆盖适配文件。普通插件安装脚本保留，但联网安装、离线安装和具体插件功能尚未验证；离线覆盖中心核心同样可能破坏适配。

## 已通过的验证

1. 镜像回读后，3,588 个路径的文件内容、符号链接、模式、UID/GID 与打包目录一致，未混入 macOS 扩展属性。
2. 651 个 UBI EC/VID 头、28 个静态卷数据块、256 个卷表记录、52,244 个 UBIFS 节点及整包 WFI CRC 均通过；UBIFS 格式为 4。
3. 官方启动区域、型号尾标、`rc`、保留的 HTTPd、UU 页面及全部内核模块通过字节比对。
4. ARM 仿真中，缺少/错误会话、跨站 POST、缺少来源信息和编码路径请求被适配层拒绝；合法读写及普通页面路径通过。实际打包的 httpdb、skipd/dbus 已完成数据库读取联通测试。
5. 页面文件映射的 ARM 测试见 `filemap_tests.log`。

**认证测试中的官方登录边界是模拟程序。** 使用真实 ARM 适配库、真实软件中心后端以及官方 libc，并不等于已经运行真实官方 HTTPd 的完整登录/TLS 流程。CRC 校验也不等于数字签名验证或设备会接受此文件。

- 完整的梅林 WAN/NAT/services/mount 事件桥接没有移植；目前仅初始执行软件中心的 `S*.sh`。依赖这些事件或梅林扩展 ASP/API 的插件可能不工作。
- 内部 API 当前用回环监听和特权源端口防火墙规则隔离；规则丢失由轮询监测后停后端、修复并重启。它不是与原厂防火墙更新原子联动的实现，仍可能出现规则重建间隙，正式使用前需要完善并实测。

所以，本轮完成的是**可审查、可回读校验的开发候选镜像**，还不能把“软件中心＋UU 已可用”列为已完成。

## 停用适配的预留方式

仅在此候选固件已经启动、SSH 仍可访问时，可创建 `/jffs/localmod-disabled`，再重启管理服务：

```sh
touch /jffs/localmod-disabled
service restart_httpd
```

启动器会直接运行保留的官方 HTTPd，不加载适配库；初始化脚本也会停用软件中心。这不是对“无法启动、无法 SSH”场景的恢复保证。实机验证前仍需确认设备的官方救援恢复路径。
