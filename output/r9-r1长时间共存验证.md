# r9-r1 长时间共存验证

本轮候选为 `RT-AX86U_388_24437_localmod2_r9_r1_EXPERIMENTAL.w`，SHA256 `b99589f7cf68bedbc2687b4168abd594632c381c331290e23ddaf53276e1c9e2`。软件中心 1.9.60、UU、Fancyss 3.5.29 与 OpenVPN/dnsmasq/curl/wget/Dropbear/miniupnpd 均沿用原 r9-r1 字节。没有访问、备份或刷写路由器，没有推送 GitHub。

当前状态：600 秒预检已通过（实际约 640 秒、78 次正常查询、20 次故障操作）；两轮 3600 秒尝试均未通过，当前正在定位计划外 HTTPS EOF。安装和准备时间不计入测量时长。

## 测量方法

使用完整 Cortex-A53 系统仿真，Linux 6.12、内部 640 MiB/外部 1024 MiB、单虚拟 CPU，无外网网卡，宿主导出只读。真实 DDNS-Go 和 Fancyss 兼容包由软件中心安装，账户、证书、节点、JFFS 和 UU 数据为自有测试数据。

持续读取原厂 HTTPS 下的 DDNS-Go 状态/版本、Fancyss HTTP 状态和软件中心页面。完整内联 JavaScript 与 ROM 对照；同时查询 DNS UDP/TCP、SSH、UPnP 映射，运行真实 TUN ping、本地 Xray SOCKS/VLESS 流量、curl/wget 的校验 HTTPS 下载。DHCP 在所有服务已启动后执行真实 DORA 与租约重启检查。

16 类故障：客户端 RST、半包断连、httpdb 被杀、软件中心重启、DDNS-Go 重启、UU 重启、HTTPS 重启、重复 SIGALRM、DNS 重启、SSH 重启、UPnP 重启、VPN 客户端重启、Xray 客户端重启、NAT 重载、代理上游停止、VPN 服务端停止。长测要求每类至少两次。软件中心/DDNS-Go 计划重启可以短暂不可用，其他维护窗口的核心查询要求全部成功；正常查询异常会终止测试，不自动重放。

记录每个 PID 的实际可执行文件、FD 和 RSS。HTTPd 的可执行文件为 qemu-arm，其 RSS 包括用户态模拟器；其他服务按记录的实际执行文件解释。按 PID 分组，不能把重启前后的不同进程直接拼成内存曲线，也不能将两个 Xray 的 RSS 相加当作独占物理内存。

## 本地复现入口

```sh
cd /Users/apple/Desktop/RT-AX86U
python3 analysis/r9r1_coexist/check.py --smoke
caffeinate -i python3 analysis/r9r1_coexist/check.py
```

需要原工作仓库中的固定输入、已挂载的区分大小写构建卷和原构建环境。此入口核对原发布门禁与镜像、组装独立只读测试输入；新工具的源码/生成转换及上下游输入哈希单独写入长测报告。原 170 项发布输入不变。生成的测试副本只改名旧测试 main，并将自有 VPN 和测试仓库证书有效期从一小时延长到三小时，避免测量结束前夹具证书过期。

预检中修正的是测试准备：SSH 从等待一秒改为检测监听就绪；四分钟不足以覆盖全系统仿真中的 16 类场景，因此预检改为十分钟。没有因此修改固件或服务运行时限。

## 证据与边界

预检：`r9r1_coexist_smoke_tests.json` / `.log`。长测完成后：`r9r1_coexist_60m_tests.json` / `.log`。报告核对宿主和客户机单调时间，并保存正常查询、维护窗口、资源采样和原文件保留哈希。

Fancyss 的全局/透明代理开关保持关闭；实际 Xray 测试流量只经自有本地 SOCKS/VLESS 端点。UU 使用原厂 NTP/下载/校验启动流程和自有工作进程，没有运行真实云端 monitor 或游戏加速。服务恢复包含既有 perp/OpenVPN 自动恢复及明确安排的手动重启，不能全部称为自动恢复。

本地测试不能替代目标 4.1 内核、无线、真实 WAN/IPv6/NAT 转发、实际代理/VPN/UU 账号、实机断电和数日持续运行验收。一次小时级观测也不能证明没有缓慢内存泄漏。原 r9-r1 固件和 55 文件交付包继续保留。

首次一小时尝试在约 58 分钟因测试仓库的一小时证书过期停止：curl 返回 60、OpenSSL 返回 certificate has expired(10)。该轮不计为一小时通过，证据保存在 `r9r1_coexist_expired_cert_tests.json` / `.log`。测试仓库证书早于正式计时创建，因此需要与 VPN 测试证书一样覆盖准备和测量时间；修正只作用于生成的测试副本，原构建输入与证书校验逻辑保持原样。

第二次一小时尝试最后成功采样约 2062 秒、331 次正常查询、20 次故障操作，随后原厂 HTTPS 状态查询在响应头前遇到 EOF。该轮不计通过，保存在 `r9r1_coexist_eof_tests.json` / `.log`。原日志缺少重启后 HTTPd 与握手错误现场，已补充仅记录元数据的测试追踪和 ClientHello 信号中断对照，尚未确定生产代码归属。

后续握手中断对照已证明并修复一个原厂 TLS 连接被放弃的问题；四次无信号对照成功，四次 SIGALRM 握手全部因 EINTR/WANT_READ 断连。覆盖层修复通过 14 项握手/超时对照、六轮软件中心重启和 110 次正常查询。生产修复另建 r9-r2 候选，最终镜像回读、完整门禁及小时长测见《r9-r2长时间共存验证》；不得将该覆盖层结果算作 r9-r1 小时长测通过。
