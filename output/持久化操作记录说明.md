# 安装与恢复记录

此项变更将最近的插件安装、更新、离线安装、卸载和软件中心恢复事件保存到 JFFS。生产变更先在未修改的 r8 镜像上加载临时源码覆盖层验证；随后 r9 已重新构建、回读，并通过 `python3 build/check_history.py --candidate`。源码覆盖层结果不代表已发布 r8 具有这些功能。

## 记录内容与查询

最多保留 32 条事件，仅包含模块名、操作种类、状态、返回码、路由器时间和递增序号。内部用于判断未完成操作的启动标识、进程号和启动时间不向页面或诊断接口导出；日志、插件配置、密码、证书、账号和节点内容不进入记录。

`Module_Localmod.asp` 显示记录；`/_localmod/status` 和 `/_localmod/diagnostics` 仍经过原厂登录/TLS 会话认证，退出登录后原令牌失效。JSON 保留 schema 1 与原有字段，新增 `history` 及事件说明字段。查询不创建记录、不更新 JFFS 记录文件；目录和文件读取使用 `O_NOATIME`。原有进程数量仍不能证明服务功能或 UU 加速正常。

没有后续结束事件的开始记录，在启动标识变化或原进程消失时，仅在查询结果中推断为未结束，不改写记录。页面明确提示核验插件状态；该推断不是插件回退或安装失败的证据。正常结束的开始事件显示“后续已结束”，避免重启后误报。

## 有界保存与异常处理

记录独立位于 `/jffs/.localmod/operations`，目录仅 root 可访问；不与插件检查点、数据库或 UU 文件共用保存逻辑。两个轮换文件 `slot0`、`slot1` 各自不超过 12 KiB，包含 SHA256，用于检测意外损坏。SHA256 不是对恶意 root 修改的认证。

写入通过非阻塞文件锁串行化，先独占创建 `pending`、完整写入并同步文件，再重命名到下一份记录并同步目录。拒绝链接、硬链接、权限异常、未知文件和不连续的记录代次。JFFS 剩余空间低于 128 KiB 时不开始持久化写入。

记录损坏、存在未完成写入、空间不足或写入失败时，保留已有文件，只展示通过校验的记录。当前事件尽可能暂存在 `/tmp`，并明确标为“未确认持久保存”；该暂存会随重启消失。记录失败不会把插件操作的成功结果改为失败，也不删除插件配置、检查点或 UU 数据。空间不足时插件安装仍遵守原有安装器自身的空间门禁。

异常记录不会自动清除、拼接或重建。先导出诊断并备份配置、JFFS、插件和 UU 数据，保留整个 `operations` 目录供检查。只有确认没有插件操作进行、备份可读且异常仅涉及操作记录后，才可人工将该目录整体改名留存，再由下一次正常操作新建记录。不要删除或改名相邻的 `plugin-txn`、插件目录或 UU 数据来处理记录问题。当前页面没有清除或自动修复按钮。

## 本地验证边界

`build/check_history.py` 使用原厂 ARM HTTPd、真实软件中心数据库/安装器和原厂 UU 下载/校验流程；UU 工作进程和账号数据均为受控夹具。每次 VM 都无外网网卡，主机导出只读，唯一可写持久盘为本次测试独有的 96 MiB ext4 文件。

矩阵覆盖原厂认证、32 条保留上限、独立 Go SHA256 校验、真实在线安装/更新/离线安装/卸载、正常与被终止的进程、单份/双份损坏、链接路径、实际低空间、部分写入、重命名失败、恢复失败、跨新 VM 启动的恢复记录、连续只读查询，以及写入重命名前后强制终止 VM。每个阶段检查插件配置、数据库哨兵、UU 数据和证书；报告与日志绑定来源及底包哈希。

源码覆盖层的六次 VM 启动已通过 85 次阶段断言，对应 46 个不同检查名，详见 `history_tests.json` 和 `history_*.log`。状态页面用受控摘要检查了正常列表、刷新和未完成写入提示；原厂认证/退出和诊断导出由真实 ARM 程序验证。提取共用 SHA256 实现后重新编译的检查点助手与原助手逐字节相同，没有改变原有检查点算法。r9 最终候选也完成六次 VM 启动、85 次阶段断言；当前报告绑定 r9 镜像 SHA256，已发布 r8 附件不变。

这些检查不能替代原厂 4.1 内核、UBIFS/NAND、真实 UU 账号与加速、物理断电和实机升级验收。安装/更新检查点的既有恢复能力不因此扩展为卸载中断后自动回退。
