# 构建与早期模型的独立工作区

`run_linux.py` 只接受明确的 `--job`；在线用例另需 `--phase`，证书生成、恢复及共存用例使用本次流程独有的 `--state-id`。调用者不再覆盖仓库级 `linux_job.sh` 或 `online-phase`。`build_candidate.py`、`check_lifecycle.py`、`check_online.py` 都通过该入口执行。

每次启动复制明确列出的根目录、程序、脚本和工具，生成独立清单。目录中的硬链接只在新副本内部保留，不链接原文件 inode；清单包括内容、类型、权限、链接与别名组。原仓库、Git 数据、上游下载目录和其他任务状态不导出。

构建及早期模型需要写入指定结果，因此只有这类受控任务使用可写的独立副本；真实第三方插件继续通过 `run_readonly_linux.py` 使用只读导出。模型退出后先验证所有输入未改动，再核对所有输出均为当前用户拥有、无额外硬链接的普通文件，符合准确文件名及大小上限，然后收集结果。任意未列出的写入、输入变动或结果链接都会拒绝通过。结果总量不超过 128 MiB，控制台不超过 8 MiB，任务时限最多 180 秒。

两种执行器共用跨进程的两个 VM 槽位，每个模型 VM 使用 1 vCPU、1024 MiB 内存和零外网网卡。取消只终止当前拥有的 VM；失败保留工作区、清单和控制台。测试中的预期失败可以在完整核对压缩包内每个文件、权限和链接后转存到本地私有目录，归档及合成私钥不会上传。

证书用例仅在自己的合成状态组内传递有界的普通文件；状态组有专属标记和独占锁，不接管历史全局证书目录。复制回传采用 pending/previous 交接；发现未完成交接时停止并保留副本。用例全部通过后才清理准确匹配的自有状态组，失败保留供排查。这是本地合成数据的处理方式，不代表目标设备的 JFFS/NAND 断电恢复。

运行入口：

```sh
python3 build/check_model_isolation.py
python3 build/check_lifecycle.py
python3 build/check_online.py
```

模型隔离检查实际执行七项构建/事件/防火墙/中心/原厂登录及 UU 作业，另从新生成的私有 UBIFS 独立回读全部路径、字节、类型、链接、权限、归属和扩展属性。原候选镜像与原 UBIFS 不会替换。负面对照让来宾成功退出后分别制造输入篡改、结果链接和清单外写入，确认宿主拒绝收集；两台真实 VM 同时就绪后，取消其中一台并确认同伴正常完成。报告 `model_isolation_tests.json` 绑定候选镜像和最终执行器源码哈希；证书及在线流程报告另保存各自作业回执。

输入准备、编译和向准确命名结果路径的收集仍按顺序运行；不要任意并发执行两个完整检查器。工作区清单防止意外的输入污染，不防御恶意宿主 root。完整 `release` 门禁包含此项，CI 快速检查本身不启动 VM。

官方升级时，`sources/localmod/` 的适配源码和这些回归入口可以复用。先用 `base_migration.py --image 新底包路径` 比较固定基线，再审查变化、更新依赖和版本、组装新候选并执行完整门禁。符号存在和文件差异检查是前提；任何不同底包都不能直接沿用旧候选的兼容结论，也不会自动迁移或刷机。

## r9 验证结果

16 项隔离检查通过，包含七个实际作业、3608 路径 UBIFS 回读及所有负面对照；证书/共存 17 项和在线流程 28 项通过最终入口重跑。原 r9 镜像 SHA256 为 `02ae38a3c0a4fc0942a0608512dd0ab2a9609d2dcf97641e486d9741febd1e50`，原 UBIFS 未替换。私有新 UBIFS 的容器字节可以因生成元数据而不同，所有内容、类型、链接、权限、归属与扩展属性仍独立比较；不以整包 SHA 相同代替语义回读。
