# localmod2-r6 插件安装中断恢复

本轮只做本地隔离验证，没有连接、备份或刷写路由器。r6 是实验候选版。新封存格式仅保护已成功建立的检查点，不能补回以前未保存或已经丢失的字节。

## 检查点损坏或恢复空间不足

出现校验、格式、目录或空间错误时，软件中心停止启动并继续拒绝写入。当前文件、封存记录以及已经隔离的中断数据库均保留；只有本次新建的重放数据库进程会在失败后被结束。原厂登录/TLS、日志及 UU 原生入口仍可使用。

不要删除 `active` 或无效标记来解除门禁，也不要给损坏数据重新计算封存值来让它通过。先私下备份所有可用副本，再从已知正确的备份修复缺损文件，或释放其他经过确认可清理的数据所占空间；然后正常重启。没有正确备份时，哈希只能发现损坏，不能恢复丢失内容。

预检保守保留 `2 MiB + 3 × 逻辑数据库记录字节数`，不保证每种闪存故障都能靠预检避免；运行中写入或提交失败仍会安全停止。恢复提交后会重开原厂数据库并核对完整键值集合，确认从磁盘读取的内容一致后才放开软件中心。

活动的 r5 版本 1 检查点缺少可信清单，r6 会保留并要求人工核查，不自动采用。对于没有活动旧记录的正常 r5 安装，现有插件和配置仍沿用原来的受管理核心升级规则。

## 中断后如何处理

1. 软件中心提示安装中断或要求恢复时，停止继续安装、更新、离线上传和保存插件设置。管理服务会对软件中心 POST 请求返回 HTTP 423；原厂登录、日志读取和 UU 页面继续保留。
2. 正常重启路由器。恢复在软件中心和插件启动前运行：只有元信息能确认尚未执行安装脚本的准备阶段才清理未完成副本；已经进入脚本的事务必须通过校验和空间检查，才会恢复安装前文件和数据库。
3. 启动后检查原插件版本、配置文件、网页设置和实际服务，再检查 UU 缓存、账号状态及加速。验收通过后才重试安装。若恢复报错，保留日志和全部事务目录，先排查空间、存储或备份损坏原因。
4. 不要手动删除 `/jffs/.localmod/plugin-txn/active`、覆盖数据库或清空 JFFS 来解除锁；那会丢掉当前可用的恢复依据。恢复失败会保留副本并停止启动软件中心。

## 保存和回退的范围

新格式同时封存每条路径、类型、权限、归属、文件和链接内容及数据库结构；校验在移动恢复目标前完成。安装脚本执行前，平台在私有 `/jffs/.localmod/plugin-txn/active` 下保存整个 `/jffs/.koolshare` 文件树及 skipd 的逐条键值记录。普通配置文件保留字节、权限、所有者和修改时间；符号链接保留为链接，不跟随到外部路径。FIFO、socket 和监督器临时控制目录不作为用户配置复制。换行、引号、美元符号等数据库内容以长度记录存储，恢复不执行 `eval` 或导入 shell 代码。

检查点需要额外 JFFS 空间。空间预检或复制写入失败时，不运行安装脚本；平台不会为了腾空间删除插件配置、UU 数据或以前的恢复记录。后台服务同时写入多个配置文件、外置 USB 目标、NVRAM、其他 JFFS 路径、ACL/xattr 以及任意高权限安装脚本的外部改动不在此回退范围内。

恢复时存储中仍可读取的中断文件树和原始数据库保留在私有 `recovered-<启动标识>` 目录中，不覆盖旧记录。数据库重放再次中断时，其部分结果也另行保留。历史记录可能含插件令牌或账号数据，不应上传到公开 GitHub；它们占用空间且不会自动清除。只有在配置、服务及备份确认后，才由管理员另行决定如何归档或清理。

每次恢复也记录启动标识，拒绝同一次启动中的重复恢复入口，避免移动已启动的数据库；恢复本身再次中断后，应再次正常重启。

同一启动周期不自动回退：被杀的安装父进程可能留下仍在写文件的子进程。只有新的启动标识才能进入回退。已完成数据同步并封存提交标记的更新保留新版；平台先持久化撤下事务目录，再删除检查点，避免清理再次中断后误回退。

离线安装与在线安装共用锁及持久化检查点。离线清理只删除此次提交的上传文件和本次拥有的解压目录，不再全局删除 `/tmp/*.tar.gz*` 或其他上传包。卸载仍沿用现有退出码与模块边界保护，本轮没有为任意卸载脚本增加事务回退。

## 本地证据和边界

本轮新增 11 类损坏/空间场景、94 项检查及 23 次独立虚拟机启动全部通过；原有 11 类中断回归的 69 项检查通过。失败停止后继续检查原厂登录/TLS、UU 控制流程及文件保留；可信修复或释放空间后，在新虚拟机中核对约 1 MiB 插件键值、原文件及恢复后重试。夹具异常和分段续跑情况见候选版说明及报告。

`recovery_safety_tests.json` 记录损坏及空间不足场景，`interruption_tests.json` 记录原中断回归，两者绑定最终镜像 SHA256；`interrupt_*_*.log` 记录各次启动。使用无网卡虚拟机、只读宿主工作区和唯一的自有 96 MiB ext4 磁盘，按边界直接终止虚拟机进程，再以同一磁盘启动新虚拟机。该磁盘为测试创建的普通文件，没有传入物理磁盘或路由器。

验证包括下载中断、未封存检查点、杀父进程、杀进程树、离线更新、新插件安装、真实 DDNS-Go 更新、提交前后、提交清理中断，以及检查点写入 ENOSPC。恢复文件树隔离之后、数据库部分重放之后也再次终止虚拟机，检查下一次启动能继续恢复。

配置检查包含 YAML、二进制文件、多行及引号数据库记录、其他插件配置、真实 DDNS-Go 旧版本配置及自启网页；自有迁移夹具先同步其半完成状态，再杀进程，验证已落盘的中断现场保留；突然掉电前尚未落盘的新数据不能保证保存。UU 检查使用合成缓存、校验文件、用户状态及临时下载数据，保留原厂 NTP→下载→校验启动控制代码，monitor 和心跳进程为自有测试实现。证书存档也逐字节核对。

这证明指定软件路径在测试环境中的中断恢复行为，**不能等同于实机 NAND/UBIFS 断电耐久性、原厂 4.1 内核兼容或真实 UU 账号/加速已验证**。虚拟磁盘采用 ext4 日志及完整宿主同步，关闭非必要的新元数据校验特性以兼容最小测试内核；磁盘、私钥、测试账号文件和第三方插件包不发布。

上游 Linux 4.1 的 [UBIFS 目录操作](https://github.com/torvalds/linux/blob/v4.1/fs/ubifs/dir.c#L1115-L1125) 提供目录 `fsync`，其 [同步实现](https://github.com/torvalds/linux/blob/v4.1/fs/ubifs/file.c#L1235-L1269) 同步 inode 及写缓冲。这项源码核对支持采用文件/目录同步的设计；它不等于运行过华硕具体内核或验证过实际闪存。
