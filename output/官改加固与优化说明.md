# 官改后续加固与优化

本轮按六项计划执行，进度见 [后续完善进度](后续完善进度.md)。早期新增检查使用原 r7 根目录上的**临时源码覆盖层**，报告明确记录底包哈希、覆盖文件及未重建镜像，不冒充已发布 r7 的新行为。最终 r8 回读和组合检查另见 `verification.json`、`hardening_tests.json` 与 `release_gates.json`，仅以实际通过的报告为准。

## 插件安装边界

原名称检查能接受文件名都在模块目录内、但链接目标越界的归档。新增 `archive-guard` 在调用原厂 tar 前完整读取并校验 gzip/tar：压缩输入最多 64 MiB、展开流最多 128 MiB、单文件最多 64 MiB、最多 8192 个条目、解析最多 20 秒；验证校验和、gzip 完整结束、单模块目录、类型、重复路径、权限、链接父目录及目标。

支持 USTAR 普通文件、目录、安全相对软链接及指向先前普通文件的硬链接。拒绝越界/绝对链接、链接链、在链接下解压、特殊设备/FIFO、重复/穿越路径、危险权限、超量或损坏包。未知扩展、PAX/GNU 稀疏等记录在解压前拒绝，不能据此承诺所有第三方归档兼容；六个已固定的真实 HND 包均接受。

在线下载由 `plugin-run` 限制为 90 秒和 64 MiB；安装/卸载脚本限制 300 秒。超时终止本次拥有的进程组，保留检查点并要求恢复，不杀已有软件中心数据库或 UU。该约束不能沙箱化任意 root 脚本，主动逃出进程组或任意外部写入仍在原恢复范围之外。

[归档与流程结果](installer_boundaries_tests.json)：28 个归档对照与 19 项流程检查通过，包括在线/离线拒绝、正常后续更新、超时子进程、恢复门禁、配置/证书/UU 数据保留。短预算夹具调用同一生产执行器验证超时，生产脚本仍使用固定 300 秒。

## 事件及日志容量

普通异步队列最多 128 条，额外为屏障预留 8 条；并发生产者在同一锁下检查容量并写入。满队列明确返回失败、记录限额日志，**不悄悄替换或重排 WAN/挂载事件**。调用方须查看饱和日志并在恢复后重新触发必要操作，不能声称任何事件风暴下都无丢失。同步前置钩子独立执行，屏障继续等待此前已接受事件。

bootstrap、事件、skipd，以及在线安装、离线安装及其备份日志，各保留当前和 `.1` 两份，每份最多 128 KiB；已有超大日志先截取尾部再轮转。噪声钩子和后台输出走有界日志读取器，保留任务退出结果。日志读取器通过 exec 释放继承的 CLOEXEC 服务锁；不遍历并关闭 QEMU 的私有宿主描述符。

[资源边界结果](resource_bounds_tests.json)：10 项检查通过。256 个并发事件准确接受 128 个，其余返回背压；验证排队顺序、一次交付、同步钩子、屏障、排空后恢复、后台/噪声输出、旧日志轮转和插件日志完成标记，以及软件中心重启后的数据库、证书、私有 API 与 UU 保留。

### 开关读取的分段输出竞态

完整事件回归发现原 `rc_bridge.c` 的脚本开关读取存在早关管道问题：读到首批 `1` 就关闭读端，工具随后写换行会收到 SIGPIPE，正确启用状态被当成查询失败。新增分段输出夹具在旧逻辑下稳定漏掉全部后置钩子，见 [复现记录](candidate_hooks_split_output_baseline.log)。修复在同一 2 秒单调时钟预算内读到 EOF，并在剩余预算内等待工具退出；不重复执行查询，超量/超时继续关闭扩展。最终事件回归包含分段输出场景。

## HTTPd 内存与并发

[原 r7 分层观测](httpd_memory_tests.json) 完成六轮四客户端、243 次独立状态/版本查询与六次异常连接关闭，另验证退出失效和重新登录。每轮空闲 30 秒；首末空闲目标 RSS 增 244 KiB，QEMU 原生映射仅增 8 KiB，FD 保持 6、线程保持 2。这表明不能把增长全归给 QEMU。

[TLS 缓存取证](httpd_cache_tests.json) 在原厂 TLS 代码中只读采集公开缓存计数与 `mallinfo`，不记录会话标识或密钥。原厂容量为 20480 条、超时 7200 秒；100 次新握手约增加 200 条缓存记录及约 116 KiB 分配器用量。新发现支持大容量 TLS 缓存造成该负载下的增长，不能逐页回填为旧一小时日志当时未采集的原因。

适配层仅将 OpenSSL 内部可恢复会话缓存限制为最多 256 条、最多 300 秒，不增加更严格原设置的容量/时长。原厂程序、协议/密码套件、证书、密码和 Cookie 验证仍保留；缓存淘汰交给原生 OpenSSL。[覆盖层对照](httpd_cache_bounded_tests.json) 中，缓存达到 256 条后保持上限；之后 100 次新握手，分配器用量从 292288 到 292184 字节；恢复连接阶段 100 次中 99 次成功复用会话。该优化缩短 TLS 恢复窗口，不改变路由器登录 Cookie 的有效期。

接口含义见 [OpenSSL 会话缓存文档](https://docs.openssl.org/1.1.1/man3/SSL_CTX_set_session_cache_mode/) 与 [OpenSSL 1.1.1 公共接口](https://github.com/openssl/openssl/blob/OpenSSL_1_1_1-stable/include/openssl/ssl.h)。缓存/分配器统计不是对象级泄漏证明，有限负载仍不能排除其他长期增长；最终新镜像还需原厂认证/TLS 与故障回归。

## UU 网络异常与恢复

[原厂 UU 故障对照](uu_recovery_tests.json) 9 项检查通过：在已有测试工作进程常驻时，分别注入 DNS 传输不可用、API 503、无效响应、下载截断、校验失败及 NTP 延迟，再执行受控网络恢复与新 NTP 周期。失败下载不执行 monitor，重复同一周期不重复启动；软件中心、数据库、证书和 UU 合成持久/临时数据保留。

原厂一次性 NTP 下载策略保持原样：此检查**不证明失败后同一周期会自动重试**。显式恢复对照使用新的原厂 NTP 控制周期。DNS 注入位于受控传输边界，WAN 是事件通知；没有测试物理 DHCP/PPP、真实公网 DNS、UU 账号/权益或加速流量。

## 状态、恢复与脱敏导出

`Module_Localmod.asp` 展示可识别服务进程数、JFFS 空间、检查点存在状态和本次开机的最近插件操作，并提供恢复步骤和 JSON 摘要导出。页面和两个只读接口均经原厂认证；没有新增认证例外。状态摘要直接读取有限的进程/空间/元数据字段，软件中心停止时仍可用；不依赖数据库查询或运行任意命令。

[初次覆盖层验证](health_tests.json) 包括无 Cookie/无效 Cookie、退出后失效、停止后查询、异常检查点、写门禁和秘密字段不出现。浏览器使用受控摘要完成实际页面与刷新检查，布局和中断提示可见；不代表真实路由器浏览器会话验收。最终新增只读方法和最近操作检查包含在 r8 组合报告中。

诊断采用白名单，不导出原日志、数据库、配置、Cookie、证书或 UU 账号；模块名仅接受短 ASCII 标识。进程数量不等于服务健康；检查点存在不等于副本封存完整性通过。最近操作记录保存在临时目录，重启后清空。异常副本不提供自动清除或强制继续安装入口。

## 验证边界

全程不连接、备份或刷写物理路由器。测试 UU 为原厂控制流加自有 monitor/心跳进程，真实账号、加速效果、原厂内核/NAND、无线/NAT 和多天实机运行保持未验证。


当前 r8 候选：`RT-AX86U_388_24437_localmod2_r8_EXPERIMENTAL.w`，85721108 字节；SHA256 `5b643b9555a27a0aa48f00640fad962fec5bcff7c9d24b4705a35898e93bf129`。回读 3605 个路径、52488 个有效 UBIFS 节点；完整 gate 以报告最终状态为准。

恢复夹具在单 CPU 下暴露约 4 秒就绪轮询窗口过紧的问题；新观测记录 DDNS-Go 约 3.98 秒才可访问。测试改用 20 秒的单调时钟上限并记录实际就绪耗时，固件 DDNS-Go 与其监督策略不变。该调整不把超时当作成功，仍要求真实网页、配置及进程符合预期。


## TLS 输入阶段的信号中断

低空间恢复重试时曾观察到一次安装日志 HTTPS 查询 EOF，原日志保留在 `candidate_recovery_tls_eof_baseline.log`。该次未采集 TLS 输入元数据，不能追溯断言其唯一原因。三轮新副本恢复对照均通过。

随后输入阶段信号控制在 r7 来源适配库和未修复 r8 中稳定得到 400。原厂 `SSL_read` 返回 `-1/EINTR`，`SSL_get_error` 为 `SSL_ERROR_WANT_READ`（2），socket 接收超时 5000 毫秒，但 stdio 层将其当作 EOF。适配层只恢复这个可重试读取，保持同一 TLS 对象/缓冲区/参数，不重发 HTTP 请求。使用单调时钟从原 socket 预算扣除已用时间，结束后恢复原超时；不重试真实 EOF、普通超时或致命 TLS 错误。零超时或不支持的句柄继续原行为。

初次覆盖层对照：4 个信号请求由全部 400 变为全部完整 200；12 次连续信号下，无输入连接约 5.01 秒关闭，预算未被延长。最终候选还加入请求行之前及请求头中断，并核对输入静默预算。细节见 `tls_input_tests.json`；OpenSSL 的可重试/致命错误语义见 [官方 SSL_get_error 文档](https://docs.openssl.org/1.1.1/man3/SSL_get_error/)。


## 最终 r8 结果

完整门禁 `release_gates.json` 通过。最终镜像的新增组合检查 `hardening_tests.json` 使用回读后的实际字节，不加载早期源码覆盖层：28 个归档对照、19 项安装流程、10 项资源控制、9 项 UU 故障、15 项认证状态/脱敏检查，以及 300 次缓存对照和六轮共存运行均通过。

六轮四客户端共 243 次查询成功、六次部分 TLS 连接关闭后恢复正常查询；原厂 HTTPd PID 未变，FD 始终 6、线程始终 2。六个空闲末目标 RSS 为 7340、7356、7356、7356、7356、7356 KiB（首末 +16 KiB，后五轮相同）；QEMU 原生映射为 15804、15812、15812、15812、15828、15828 KiB（+24 KiB）。观测约 348 秒，不能据此保证多天或实机无泄漏，也不能把这些 HTTPd 数据回填为旧 DDNS-Go 1.34 MiB 的原因。

最终输入阶段对照中，旧适配库在请求头中断 4/4 返回 400、请求行前中断 2/2 出现 EOF；新候选的十个 GET 均完整成功。POST 正文中断后脚本执行一次且返回 200；旧对照返回 503、未执行脚本。12 次持续信号下，静默连接约 5.004 秒关闭。认证、证书、密码及应用写请求均未由夹具绕过或自动重发。

另外，最终镜像完成 17 项证书与共存、28 项在线、32 项真实插件、18 项 HTTPS、69 项中断和 94 项损坏/空间回归。完整运行结束后仅更正了汇总器对成功状态 `FAILURE_SAFETY_PASS` 的文本判断，并补充宿主冒烟失败元数据；所有固件与测试源码保持运行时版本，生产程序再次编译与回读一致。此前一次宿主冒烟初次失败未留下返回码/耗时，独立三轮均返回 124、约 1.2–1.4 秒；补充元数据后的完整最终核对通过。没有据此改动固件超时策略。

实机、真实 UU 账号/加速、无线/NAT、NAND/UBIFS 断电及多天运行仍待单独验收；未连接或刷写物理路由器。

发布阶段另修正附件传输命名：中文文档以固定 ASCII 别名上传，内容和 SHA256 保持一致；固件和运行测试源码未因此变化。
