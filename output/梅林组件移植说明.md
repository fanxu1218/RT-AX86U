# localmod2-r9-r1 梅林组件移植

官方底包仍为 ASUS RT-AX86U 3.0.0.4.388_24437。选取 Merlin `3004.388.12_2` 的六个 ARM32 程序及必需私有依赖；没有移植梅林 VPN 页面、`rc` 控制平面或 `libovpn`。本地构建与全部回归是否完成，以同镜像 SHA256 的 `verification.json` 和 `release_gates.json` 为准。

| 组件 | 所选梅林版本 |
| --- | --- |
| OpenVPN | 2.7.6 |
| dnsmasq | 2.93 |
| curl | 8.17.0 |
| wget | 1.25.0 |
| Dropbear | 2026.94 |
| miniupnpd | 2.3.11 |

六个标准入口默认分发至 `/usr/libexec/localmod/merlin/bin/`。只修改这些程序的 ELF RPATH，私有依赖位于 `/usr/lib/localmod/merlin/`；应用代码段与八个依赖原始字节经过独立检查。私有依赖包括所选固件的 OpenSSL 1.1.1w；这不是把整套固件升级到最新 OpenSSL。原厂的 HTTPd、全局 TLS/PAM/NVRAM/共享库、内核、驱动和 UU 文件继续保留，避免新版库影响登录、认证及其他原厂服务。多调用入口和原厂查找/停止进程所用的别名保留。梅林 curl 不包含原厂 curl 的数字地址拦截；测试分别确认新版可访问数字地址、保留的原厂程序仍拦截，并验证回环回调。软件中心 API 的回环绑定、认证转发和防火墙隔离继续生效。

## 兼容适配

原厂禁用 NCP 的服务端配置包含 `ncp-disable`，直接交给 OpenVPN 2.7 会拒绝启动。对原厂 `/etc/openvpn/client1..5/config.ovpn`、`server1..2/config.ovpn` 中的 `ncp-disable` 或静态密钥 `secret`，启动器自动选择保留的原厂 OpenVPN；显式命令行对应参数也支持。配置、证书、密钥和加密选项均不改写。现代配置默认使用 2.7，原厂 `libvpn.so` 实际生成的客户端配置已做本地解析检查；原厂 PAM 插件验证了正确密码通过、错误密码拒绝和真实 TUN 测试流量。

这是一条兼容路径：上述旧模式仍运行原厂旧程序，不获得 2.7 的全部修复。选择器有意不代替完整配置解析器，不追踪任意包含文件或未知旧参数；自定义复杂配置可用单组件开关回退。没有据此声明所有 VPN 运营商配置已验证。

MiniUPnPd 新版默认私网 WAN 策略和 postrouting 依赖与原厂控制流程不同。适配器只读取原厂生成配置，向受保护的 `/tmp/.localmod-merlin/` 写入运行副本；没有显式配置时保留原厂允许私网 WAN 的行为，显式 `ext_allow_private_ipv4=no` 继续生效。仅创建自己的 `LOCALMOD_UPNP` 链及 WAN 接口限定的引用，不清空插件/UU 链。PCP 第三方策略跟随已明确的 `secure_mode`。原厂 NAT restore 成功后同步恢复自己所需的链，即使用户未开启 JFFS 自定义脚本也可工作；只在新守护进程运行时恢复，不强行重启服务。当前没有承诺 NAT 重载后自动恢复全部已有租约映射。

## 本地验证边界

组件测试使用无外网网卡、宿主导出只读的临时 Linux；需要真实 iptables 兼容调用的部分采用完整 Cortex-A53 系统仿真和内核 ARM32 兼容执行。测试数据、接口、证书及账号均为自有夹具。未适配版本私网 WAN 和缺失 postrouting 链的真实失败对照见 `output/merlin_upstream_incompatibilities.json/log`，状态为 `BASELINE_REPRODUCED`，不是候选通过报告。同候选六组件服务组合已通过 19 项检查，其中 SSH 用原厂工具分别生成 RSA/ECDSA/Ed25519 主机密钥，新版读取与认证后文件内容一致；SSH 密码登录模式另待实机验收。单服务阶段证据在 `build/merlin_*_probe.json/log`，最终候选报告为 `output/merlin_component_tests.json/log`，阶段报告不能代替候选报告。

覆盖版本与原厂回退、DNS UDP/TCP 连续查询/重载/重启/断连、实际 DHCP DORA 与租约、curl/wget HTTPS 下载及证书拒绝、SSH 原厂格式主机密钥/客户端认证/重启/拒绝错误身份、UPnP SOAP 与实际内核规则、原厂 NAT 重载后的链恢复、OpenVPN 相互认证/TUN 流量及 PAM 认证。UU 使用原厂下载校验/启动流程和受控工作进程，核对单实例和自有数据；没有访问真实 UU 账号或证明游戏加速。软件中心、DDNS-Go、Fancyss、FRPC、PushPlus 的安装更新卸载及故障恢复由其他候选绑定报告覆盖。未开展新的小时级长测，旧 r7 的长测不能当作本版本证明。

尚未验证物理路由器启动/刷入、目标 4.1 内核、无线/IPv6/真实 WAN 转发性能、NAT-PMP/PCP 实际协议流量、外部 VPN 服务、真实代理节点和 NAND 断电。没有刷机或推送 GitHub。

## 运行开关与回退

以下命令仅供将来已备份并获安排后的实机排查；本轮未在路由器执行。创建标记后需通过原厂界面重启相应服务，或安排重启设备，已经运行的进程不会因标记自动替换。

- `touch /jffs/localmod-merlin-disabled`：六个组件均使用保留的原厂程序；删除标记并重启服务恢复新版。
- `touch /jffs/localmod-merlin-openvpn-disabled`：仅 OpenVPN 使用原厂程序；其他五项保持新版。
- 原有 `/jffs/localmod-disabled` 是整个 localmod 的停用入口，影响范围更大。

原厂程序位于 `/usr/libexec/localmod/merlin/vendor/`。这些开关不清除 NVRAM/JFFS/插件/UU 数据，也不等于固件回刷。完整刷机回退遵循《Alpha3升级localmod2与实机验收》中的原固件、已验证备份及救援步骤；不要跨版本盲目恢复设置。
