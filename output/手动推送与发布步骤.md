## 只推送源码和报告

```sh
cd /Users/apple/Desktop/RT-AX86U
git status --short
git log -4 --oneline
git push origin main
```

`git status --short` 应为空；如已有你自己的修改，先处理自己的工作，不直接混入本轮提交。普通 `git push` 会同步所有尚未推送的本地提交。原有 SSH/HTTPS 网络故障需要先恢复网络；不需要重建固件、改写旧标签或强推。

推送后核对远端和本地提交：

```sh
git rev-parse HEAD
gh api repos/fanxu1218/RT-AX86U/commits/main --jq .sha
```

两者必须相同。再检查该提交的 CI：

```sh
RTAX86U_HEAD=$(git rev-parse HEAD)
gh run list --repo fanxu1218/RT-AX86U --workflow check.yml --commit "$RTAX86U_HEAD" --limit 5
```

若任务尚未出现，稍后重新查看同一个提交。确认对应的 `Source boundary checks` 结束且成功；失败时先保存日志并处理问题，不把旧提交的绿灯当作本次通过。该 CI 仅执行快速源码检查，完整本地固件验证仍以 `release_gates.json` 为准。

## 可选：创建新的实验预发布

只需要同步源码时，完成上一节即可。需要上传固件附件时，在同一工作仓库、工作目录干净、远端 main 与本地 HEAD 一致且上述 CI 成功后执行：

```sh
python3 build/publish_release.py
```

发布器核对源码、候选镜像和各门禁报告的哈希，生成当前提交的源码包和附件清单，再创建 `localmod2-r9-experimental` 新预发布。它核对远端附件长度/SHA256、旧 r2–r8 发布及 r7 注释标签；不覆盖已存在的同名发布，不刷写路由器。若上传中途报错，先检查终端日志和 GitHub 实际状态；不要直接删除发布或覆盖附件。

只有发布器完整成功、`release_delivery.json` 的标签确为 `localmod2-r9-experimental` 且状态为 `PUBLISHED_AND_ASSETS_VERIFIED`，才表示上传及附件核验完成。然后单独记录真实发布回执：

```sh
git add -- output/release_delivery.json output/localmod2_r9_release_manifest.json
git commit -m "Record verified localmod2-r9 release delivery"
git push origin main
```

后续回执提交不会移动预发布标签。实际发布后的状态说明可在后续文档提交中更新；不要把本地交付记录改成上传成功来代替真实回执。
