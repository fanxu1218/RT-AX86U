## 推送源码与报告

确认本地交付状态为 `LOCAL_VALIDATED_MANUAL_REMOTE_HANDOFF`，且工作目录干净：

```sh
cd /Users/apple/Desktop/RT-AX86U
git status --short
git log -4 --oneline
git push origin main
```

如果已有自己的修改，先处理自己的工作，不直接混入本轮提交。普通推送同步所有尚未推送的本地提交，不需要强推或改写历史标签。

推送后比较远端提交：

```sh
git rev-parse HEAD
gh api repos/fanxu1218/RT-AX86U/commits/main --jq .sha
RTAX86U_HEAD=$(git rev-parse HEAD)
gh run list --repo fanxu1218/RT-AX86U --workflow check.yml --commit "$RTAX86U_HEAD" --limit 5
```

两个提交哈希必须相同，并核对该提交的 `Source boundary checks` 已结束且成功。若尚未出现，稍后检查同一个提交；失败时先保存日志并处理原因。远端 CI 只做快速源码检查，完整固件回归仍以本地镜像绑定门禁为准。

## 可选：上传固件附件

只需要同步源码，完成上述步骤即可。需要创建新的实验预发布时，先确认工作目录干净、远端 main 与本地 HEAD 相同、对应 CI 成功，再执行：

```sh
python3 build/publish_release.py
```

发布器核对受测源码、候选和报告哈希，为 `localmod2-r9-r2-experimental` 创建新预发布，包含固件、Fancyss 兼容包、源码及软件中心/梅林说明和报告。小时共存专项报告与失败对照还包含在本地交付包中，核对《r9-r2长时间共存验证》和 LOCAL_MANIFEST.json。它不会覆盖同名发布，不刷机；原历史发布和 r7 注释标签也会核验。若上传中途报错，先保存日志并检查 GitHub 实际状态，不直接删除发布或覆盖附件。

仅当发布器完整成功，且 `release_delivery.json` 标签确为 `localmod2-r9-r2-experimental`、状态为 `PUBLISHED_AND_ASSETS_VERIFIED`，才表示上传及附件核验完成。之后单独提交真实回执：

```sh
git add -- output/release_delivery.json output/localmod2_r9_r2_release_manifest.json
git commit -m "Record verified localmod2-r9-r2 release delivery"
git push origin main
```

后续回执提交不会移动预发布标签。本地交付记录不能代替真实上传回执。
