# localmod2-r5 adapter

This experimental RT-AX86U firmware retains the exact ASUS 24437 kernel, modules, vendor rc, HTTPd and xtables-multi binaries. Small launchers relocate rc and HTTPd and preload narrowly scoped adapters. It is not device tested. See `../../output/官改候选版说明.md` and the machine-readable test reports.

## Event contract

- `rc_bridge.c` observes imported vendor APIs: WAN state writes, service-queue parsing, init's `sigwaitinfo` boundary, USB mount/unmount calls, and dnsmasq execution. Pending WAN notifications flush after the native handler reaches idle or a helper exits; forked helpers discard inherited pending events.
- `runtime.c` and `event.c` provide a root-only queue in `/tmp/.localmod`, ordered asynchronous execution, blocking pre-operation hooks, 120-second script limits and process-group cleanup. Before unmount and services-stop, a queue barrier finishes earlier asynchronous work. Unmount retries emit one stop hook per mount lifetime.
- `dispatch.sh` runs existing `/jffs/scripts` hooks, then the appropriate software-center S/V/T/N/M/U helper. Per-event context prevents a legacy user hook and the dispatcher from running the same center helper twice. User hook files are not rewritten.
- Native NVRAM reads/writes outside the observed contract pass through. The script-enable flag is read by a fresh `/bin/nvram` process, avoiding a second getter that could overwrite the vendor getter's shared buffer or a borrowed argument. Both the adapter and dispatcher honor `jffs2_scripts=0`.
- `restore.c` preserves the vendor restore program and exit status. It inserts the private API chain into the same filter-table COMMIT, emits NAT/firewall events only after successful application, and handles stdin, file input, dry-run and noflush. Explicit administration through other iptables entry points can still alter those rules.
- DNS compatibility provides `dnsmasq.conf`, `.add`, `/jffs/configs/dnsmasq.d` and `dnsmasq.postconf` before daemon launch. A generated baseline prevents repeated additions from accumulating. `helper.sh` supplies the common postconf editing helpers.

The r1 migration checks all backup destinations, including dangling links, before moving the old core. It archives the legacy `.asusrouter` symlink even when renaming the old core makes its target temporarily disappear. The installer also fixes the upstream module-specific uninstall file test.

`bootstrap.sh prepare` runs when JFFS mounts and performs a managed-core migration without copying old Alpha-3 plugins into the new center. Upgrades from an existing localmod installation retain current plugins, the database and user hooks. `start` runs at the native init idle boundary. Database shutdown first uses a bounded read barrier to commit pending writes, then waits for the old skipd process to exit; rapid service restarts retain immediately written values. Compatibility entries include `jffsinit.sh`, `kscore.sh` and `service start/stop/restart_skipd`. A recovery marker stops the private backend and allows the launchers to run the unmodified vendor binaries.

The HTTPd adapter relies on the vendor login boundary. The native-runtime job now executes the pinned vendor HTTPd, libpasswd and mssl/OpenSSL with synthetic NVRAM/shadow/certificate inputs, including real session issuance, HTTP/TLS API reads and POST callbacks, rejection and logout. The faster bridge models remain separate. It also supports encoded query values and upload query parameters without permitting encoded path traversal. Native model-specific kernel modules, arbitrary Merlin Addons APIs, every VPN/QoS hook and all third-party plugins are outside the verified compatibility set.

## Local build

The prepared macOS Apple Silicon workspace needs OpenSSL (for a synthetic shadow fixture), Zig 0.15.2, Go, Python with `ubi-reader==0.8.16` and `pyelftools==0.32`, the signed Apple Virtualization builder, pinned Alpine packages and the case-sensitive source extractions.

```sh
# Run from the repository root. Attach only if the volume is currently detached.
hdiutil attach -nobrowse -mountpoint "$PWD/build/casefs" "$PWD/build/RTAX86UBuild.sparseimage"
python3 build/build_candidate.py
```

A fresh mounted volume can be populated with `analysis/.venv/bin/python build/extract_casefs.py`. The scripts require the downloaded official and donor inputs and prepared toolchain; this is not a one-command build from a fresh clone. `--compile-only` builds the adapters and fixtures without assembling an image.

The build runs the existing API/file mapping tests, rc lifecycle fixtures, live legacy-netfilter reload probes and a controlled multipart upload, offline installation, callback and custom uninstall through the ARM32 authenticated adapter and packaged httpdb/skipd/dbus. Alpine curl, xtables and the process-launch helper are used inside the ARM64 guest; the target's old proc/iptables ABI cannot be fully exercised through user-mode QEMU. QEMU executables are given skipd/httpdb names in the lifecycle fixture so pidof/killall see the same names as on the router. These earlier fixture jobs do not install real third-party plugins or exercise external services/routers; the r4 full-rootfs jobs below provide the separate real-package coverage.

Offline CRC and filesystem checks do not establish flash acceptance, real boot, on-device TLS/login integration or production certificate lifecycle, wireless stability or UU acceleration.

To recheck the existing candidate without rebuilding or flashing it, run `python3 build/check_lifecycle.py`. It first verifies the image hash and that the tested production adapters match the staged candidate, then runs the native login/UU regression and three sequential certificate/coexistence VM jobs. `build_candidate.py` includes the same lifecycle checks after image readback, skipping only the native regression it has just completed. Do not run a second VM job or overwrite shared fixture binaries while these jobs are running.

The 17 lifecycle checks execute the original certificate generation/save/restore code and gencert/OpenSSL, including a new VM restoring only the previous VM's owned certificate archive. Generated CA trust, IP SAN, private key permissions and TLS are verified. The coexistence job runs packaged perpboot/perpd/httpdb/skipd/dbus and the production bootstrap alongside native HTTPS/rc, an owned monitor/worker and a loopback download service. It checks center/HTTPS restarts, callbacks, database retention, parallel page/API requests, legacy filter reloads, repeated NTP notifications and recovery stop. NVRAM/shadow/LAN and CPU/proc helper inputs remain synthetic; physical reboot, power loss and real UU traffic are not covered. Private test archives are deleted in `finally` and never published. See `../../output/lifecycle_tests.json`.

`verify_uu_compatibility.py` checks retained official UU resources and model-level call transparency. Its earlier command contract remains a model. The new native-runtime job executes the original rc NTP signal handler and UU control flow with an owned monitor and local download shim; the real UU monitor, accounts, discovery and acceleration remain unverified.

The r2 HTTPd launcher executes the retained program directly at `/usr/libexec/localmod/httpd`: the native path check rejects the earlier `/tmp` copy. Stdio hooks resolve lazily to handle calls before the adapter constructor. Exact `asus_token` and `asus_s_token` cookie names are supported, with native session/transport validation retained. The authenticated index handler cannot pre-read the original API body; relay owns that body after authentication.

The r3 online installer patch preserves UU archives and unrelated temporary tasks, locks online install/update/uninstall operations before reading shared request fields, owns only its private download and freshly created stage, and reports the operation result after its logging pipeline. A failed update restores the previous copied uninstaller; a nonzero custom uninstall keeps registration/configuration. Default removal respects module boundaries. The actual patched script remains derived from the pinned donor through `build/patch_online_installer.py`; runtime ownership/lock helpers live in `installer-guard.sh`.

Run `python3 build/check_online.py` against a prepared candidate for the 28 online checks; full builds include it after readback/lifecycle checks. It uses a controlled HTTPS catalog, actual vendor wget with verified fixture CA/hostname, original native HTTPS authentication, real center services and owned plugin/UU workers. Public catalog metadata is inspected read-only, and no real third-party package or UU component is executed. Numeric-IP download protection remains enabled; guest-only hostnames map the local servers to loopback. The process helper for install/uninstall is native Alpine because the packaged ARM32 helper cannot enumerate the ARM64 guest proc ABI. These earlier RAM-only jobs do not establish interruption recovery. The r5 checks below cover the defined center/skipd rollback scope; arbitrary external changes by privileged scripts remain outside it.

Center shutdown now confirms supervisor exit before stopping the API worker, with bounded retries and a stateless-process fallback. This prevents a late supervisor restart from leaving httpdb active after recovery stop. The skipd read/commit barrier is retained and the database is never force-killed.


## Real HND plugin checks (r4)

`python3 build/check_real_plugins.py` fetches six SHA256-pinned inputs for Alibaba DDNS, DDNSTO and DDNS-Go, then runs 32 checks across genuine old-to-current upgrades and independent current-version installs/uninstalls. DDNS-Go 1.28.0 is packaged without file changes from a pinned upstream tree; the other five are original archives. Host preflight inspects archives without extracting or executing their contents. `build/real_plugin_sources.json` records provenance and the distinction between catalog and internal versions.

The `--readonly` Virtualization mode has no NIC or disk devices and exports the workspace read-only. A disposable RAM chroot copies the complete candidate, mounts real guest proc, and uses ARM binfmt_misc F with static QEMU. Actual ASUS curl/wget and the packaged process helper now run; only synthetic NVRAM/account inputs and the guest-native xtables ABI boundary remain. Test output is bounded serial JSON, not a writable host results share. Do not run another VM job or rebuild shared fixture binaries while a job is active.

Full-rootfs reproduction found incorrect shell PATH ordering (`/usr/sbin/sh` is a vendor memory tool), vendor curl's numeric-URL rejection, missing tee/xargs applets and a registered plugin's empty runtime-directory conflict. r4 corrects the owned PATH/callback/installer contracts. The original BusyBox and curl stay unchanged; a private pinned donor BusyBox exposes only tee/xargs. `rmdir` can reclaim only an empty real directory of an installed module; other preexisting state is preserved. Earlier Alpine-root fixture reports did not cover these vendor-tool differences.

The report separately records genuine third-party package execution and the owned UU worker. No real UU monitor/account, cloud DDNS/tunnel service or router is exercised. Public downloads still need WAN/DNS/default-CA verification on the device.

## Persistent install checkpoints (r5)

`plugin_txn.c` stores an intent, a no-follow copy of the center tree and length-delimited native skipd records under root-only `/jffs/.localmod/plugin-txn/active`. Online and standard HND offline installs checkpoint before any installer/uninstaller replacement. Preparation/ENOSPC errors abort before mutation. Failed or killed installers block subsequent software-center POSTs with 423 and require a new boot before rollback; the native login/TLS and UU paths remain available. A detached watcher reports owner death using PID plus start time.

Early bootstrap restores the tree before starting plugins, then replays literal database records into a fresh skipd database. Interrupted new state and raw databases are retained in private recovery history; there is no automatic history deletion. Recovery renames are restartable across boots. A separate recovery-boot identity refuses duplicate preparation over a live/partially replayed database in the same boot. Commit requires the native read barrier and data sync, followed by a durable commit marker. The active journal is durably detached before garbage collection so a cut during deletion cannot undo a committed update. Checkpoints do not cover NVRAM, USB/symlink targets, arbitrary installer writes elsewhere or concurrent background file writers.

`python3 build/check_interrupt.py` is included after image readback and real-package checks. It allows one owned 96 MiB virtual disk under ignored `build/interrupt-private/`, with full host synchronization and a read-only workspace, no NIC or physical disks. A test-only ARM interposer and cp wrapper stop execution at explicit boundaries; genuine DDNS-Go archives stay unchanged. The VM is terminated without guest shutdown, then a new VM resumes with the same ext4 disk. Tests cover preflight/download, checkpoint preparation, SIGKILL of parent/tree, fresh/offline installs, authentic DDNS-Go update, before/after commit, detached commit cleanup, write ENOSPC, and interruption of tree recovery and partial database replay. Firmware never includes the fault interposer or wrappers.

See `../../output/interruption_tests.json` and `../../output/插件安装中断恢复说明.md` for bound-image evidence and scope. Exact synthetic configuration, binary bytes, multiline/quoted database values, unrelated state, UU cache/user-state files, TLS archive and DDNS-Go autostart/page are checked. Physical NAND/UBIFS power cuts, original 4.1 kernel behavior and real UU accounts/acceleration remain unverified. Do not upload fixture disks, recovered user databases or credentials.
